# 01.02 Reading a key

The arrows, Home, End, Delete, Page Up and Page Down each send several
bytes. This lesson reads them back as one key each, and tells the Escape
key apart from them by how long the next byte takes to come.

## Where this fits

![Where 01.02 fits](figures/01.02-map.svg)

This lesson builds read a key, the step between the terminal and the key
handler on the way down the left side of the map. Above it, raw mode hands
over bytes as they are typed. Below it, the key handler switches on keys.
After this lesson an arrow arrives as one key, 1002 for Up, and so does
every other key kilo uses, which is what lets module 03 move a cursor with
them.

## The idea

![editorReadKey(): a byte that is not 27 is the key; after a 27, two more bytes within a tenth of a second each name the key, and no byte means Escape.](figures/01.02-decode.svg)

At 01.01, the Up arrow printed three lines: `27`, `91 ('[')`, `65 ('A')`.
A key handler that switched on bytes would see the Escape key, then a `[`
and an `A` typed as text. The bytes of a sequence have to be put back
together into one key before anything acts on them.

The trouble is the first byte. 27 is also what the Escape key sends, on its
own. What differs is what comes after it, and when. A terminal writes all
the bytes of a sequence at once, so by the time kilo has read the 27, the
`[` and the `A` are already waiting. After the Escape key nothing comes
until you press another key, and to be taken for an arrow you would have to
type `[` and a letter each within a tenth of a second of the one before.

So: read a byte. If it is not 27, it is the key. If it is 27, try to read
two more, each with the tenth-of-a-second timeout raw mode set up in
01.01. If either does not come, the key was Escape. If they come, they say
which key it was: `[` and `A` is Up, `[` and `3` is the start of Delete,
whose `~` is one more byte to read.

![Up's three bytes come in one write and are one key at once; a lone Escape becomes a key after the 0.1 s wait; Escape and then [ A half a second later are three keys.](figures/01.02-timing.svg)

### `editorReadKey`

Waits for a byte, going round as often as `read()` comes back empty after
its tenth of a second. A byte that is not ESC is returned as it is. After
an ESC it reads up to three more bytes and turns `ESC [ A` to `ESC [ D`,
`ESC [ H`, `ESC [ F`, `ESC O H`, `ESC O F` and `ESC [ 3 ~`, `ESC [ 5 ~`,
`ESC [ 6 ~` into one code each, or returns ESC itself when the bytes stop
coming. If `read()` fails, kilo exits.

### The key codes

The enum of keys gains nine names, `ARROW_LEFT` = 1000 up to `PAGE_DOWN` =
1008. They are kilo's own numbers, not bytes: above 255, so no byte can
ever be mistaken for one, and an `int` holds either.

### `editorProcessKeypress`, now with keys

It gets its key from `editorReadKey()` instead of reading a byte itself, so
the codes it prints are keys now, not bytes. A case for ESC that does
nothing joins the switch: Escape is a key with no job yet.

## How it works

### One byte at a time, and no more than one key

`editorReadKey()` reads one byte per `read()`, never more. So it takes out
of the driver's queue exactly the bytes of one key, and whatever came after
it stays queued for the next call. Keys do pile up in the queue, from a
paste or while kilo is busy: all ten keys of the run above, sent in a single
write, still print one line each, because each call stops at the end of its
own sequence. Every byte the terminal sends has to be read by exactly one call;
Break it shows what becomes of a byte that is not.

### Every read may come back empty

Each `read()` after the ESC can return 0, meaning the tenth of a second
passed with nothing. Each of them is checked, the third one as well:

```
                    if (read(fd,seq+2,1) == 0) return ESC;
```

so a sequence cut short is Escape, never a half-read key. The same timeout
makes Escape followed by `[` and `A` typed by hand three keys, not Up:
pressed half a second apart, they print `27`, `91 ('[')` and `65 ('A')`.

### A sequence kilo does not know

Insert sends `ESC [ 2 ~`. kilo reads all four bytes, finds no case for a
`2`, and leaves the inner `switch` with `break`. The `while(1)` around it
goes round with the key still ESC and reads on. Nothing more comes, so
after a tenth of a second the key is Escape, the 27 of the run above.

One cost of going round: whatever arrives within that tenth of a second is
taken as the start of another sequence and lost. Insert followed at once by
`abc` prints only `27`, and so does Insert with an `a` typed 50 ms after
it.

## Decide the boundary

kilo waits a tenth of a second after an ESC, because that is what `VTIME`
1 gives. Over a slow network link the bytes of one sequence can arrive with
a gap between them, and if the gap is longer than the wait, kilo reads
Escape and then `[A` as text. Another editor could wait longer and be safe
there, and every press of Escape would take that much longer to act on; or
it could wait less and feel quicker, and split more sequences. Which do you
want right more often: the Escape key, or the arrows on a slow line?

## Break it

Read a sequence short. In `build/at/kilo/01.02/kilo.c`, in
`editorReadKey()`, replace the read of the third byte of `ESC [ digit ~`,

```
                    if (read(fd,seq+2,1) == 0) return ESC;
```

with a line that assumes the `~` is there instead of reading it:

<!-- verify: patch file=kilo.c
-                    if (read(fd,seq+2,1) == 0) return ESC;
@block
-->
```
seq[2] = '~';
```

Run it, press Delete, Page Up, and Ctrl-Q:

<!-- verify: session run="./learn run kilo --at 01.02" wait=2 send="esc [3~ esc [5~ ctrl-q" -->
```
1004
126 ('~')
1007
126 ('~')
17
```

Each key still decodes, but its `~` stayed in the driver's queue, and the
next call read it as a key of its own: 126. From 04.01 on, any key that
is not a command is typed into the file, so Delete would put a `~` in your
text. Put the `read()` back.

  counts tenths of a second, and when it runs out `read()` returns 0. That
  0 is how kilo knows nothing followed the ESC.

  table 3-6: the cursor keys send `ESC [ A` and the rest in one mode and
  `ESC O A` in the other, the reason for kilo's `ESC O` branch.
