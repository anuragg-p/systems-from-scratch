# 01.01 Raw mode

kilo's first code switches the terminal into raw mode, where every key
reaches the program the moment it is pressed, unechoed and unchanged, and
switches it back when kilo exits.

## Where this fits

![Where 01.01 fits](figures/01.01-map.svg)

This lesson builds the terminal at the top of the map, in raw mode, and the
key handler that every key will go through on its way down the left side.
Behind the terminal box is the kernel's terminal driver, which by default
edits a whole line before a program sees any of it. Every later piece reads keys or
draws the screen through what this lesson sets up. After it, kilo runs: it
gets each key as a byte the moment it is typed, prints the byte's code, and
quits on Ctrl-Q with the terminal as it found it.

## The idea

![a, Enter and Ctrl-C through the terminal driver: in cooked mode the program gets 97 10 only after Enter, and Ctrl-C kills it; in raw mode it gets 97, 13 and 3 as they are typed.](figures/01.01-cooked-raw.svg)

Run an ordinary program in a terminal and type, and the program sees
nothing until you press Enter. The kernel's terminal driver holds the line:
it echoes each key so you can see it, lets Backspace take a character back,
and hands the program the whole line when Enter ends it. It does a few
more things on the way: the carriage return from Enter becomes a line feed,
Ctrl-C becomes a signal that kills the program, and Ctrl-S stops the output
until Ctrl-Q. That is **cooked** mode (canonical, in the manuals), and it
is right for a shell.

An editor needs the opposite. It must see each key the moment it is
pressed, draw its own screen with no echo mixed in, and keep Ctrl-S and
Ctrl-Q for itself. **Raw mode** is the same terminal with that processing
switched off. The driver's settings for a terminal are a `struct termios`:
four words of flags and an array of control values. `tcgetattr()` reads
them, `tcsetattr()` writes them back, and raw mode is eleven flags and two
values changed.

The settings belong to the terminal, not to the program: they stay as they
are when kilo exits, and the shell that comes back expects cooked mode. So
the job has two halves, raw mode on at the start and the old settings back
at every way out.

### `enableRawMode`

Saves the terminal's settings in `orig_termios`, arranges for them to be
put back at exit, and switches a copy to raw: input bytes arrive unchanged,
output goes out unchanged, nothing is echoed, there is no line editing and
there are no signals from the keyboard, and `read()` gives up after a tenth
of a second whether or not a key came. It returns -1 if standard input is
not a terminal at all.

### `disableRawMode` and `editorAtExit`

`disableRawMode()` writes `orig_termios` back. `editorAtExit()` does the same
with no arguments, the shape `atexit()` wants, so the C library calls it
however `exit()` is reached. `E.rawmode` records whether raw mode is on, so
neither half does its work twice.

### `editorProcessKeypress` and `main`, for now

`main()` checks that it was given a file name, switches raw mode on, and
calls `editorProcessKeypress()` forever. That reads one byte and acts on
it. There is no screen yet, so for now it prints the byte's code on a line
of its own, with the character beside it if it is printable. Ctrl-Q, 17,
calls `exit(0)`; Ctrl-C, 3, does nothing, on purpose: losing your changes
should not be one key away. The file name is not read yet; files come with
03.01.

### The Makefile

kilo's own: `make` builds `./kilo` from `kilo.c` with `-Wall -W -pedantic
-std=c99`, every warning on and plain C99, and links nothing but the C
library. `make clean` removes the program.

## Run it

`./learn run kilo --at 01.01` builds the project and starts it. Nothing you
type is echoed; each key prints its code instead. Press `a`, Enter, the Up
arrow, Tab, Ctrl-A, Ctrl-C, Ctrl-Z, Ctrl-S, Escape and `1`, and last
Ctrl-Q:

```

13
27
91 ('[')
65 ('A')
9

```

Every key arrived as it was pressed. Enter is 13, not the 10 a cooked
terminal makes of it. The Up arrow is three bytes, 27 91 65; putting them
back together is the next lesson. Ctrl-C and Ctrl-Z did not stop kilo: they
are just 3 and 26. Ctrl-S did not freeze anything. Backspace, if you press
it, is 127. Ctrl-Q printed its 17 and kilo exited, and the shell's prompt
is back with the terminal as it was: what you type is echoed again.

## How it works

![The flags enableRawMode() changes, field by field, and what each change does.](figures/01.01-flags.svg)

### Each flag is one thing the driver stops doing

Most of the changes are easiest to understand by putting one back and
watching what kilo sees. Here is what the project at this lesson does with
one flag left on:

| left on | what happens |
|---|---|
| `ICRNL` | Enter arrives as 10, not 13 |
| `IXON` | a, Ctrl-S, b, Ctrl-Q prints `97 ('a')` and `98 ('b')`, never 19 or 17: the driver took Ctrl-S and Ctrl-Q to stop and restart the output. kilo can no longer be quit |
| `ISIG` | Ctrl-C kills kilo at once, by the signal SIGINT |
| `IEXTEN` | on macOS, Ctrl-V never arrives: the driver keeps it to quote the next key |
| `OPOST` | each `\r\n` goes out as `\r\r\n`: harmless here |

`OPOST` off is also why the line the key printer writes ends in `"\r\n"`:
with output processing off, `\n` only moves down a row, and the `\r` takes
the cursor back to the first column. `BRKINT`, `INPCK`, `ISTRIP` and `CS8`
are about serial lines, which have breaks, parity bits and 7-bit
characters. A pseudo-terminal has none of these, but clearing the first
three and setting `CS8` means every byte arrives whole, all 8 bits of it,
wherever kilo runs.

### A read that gives up: VMIN 0, VTIME 1

`VMIN` is how many bytes `read()` waits for and `VTIME` how long it waits,
in tenths of a second. With `VMIN` 0 and `VTIME` 1, `read()` returns as
soon as one byte is there, or returns 0 after a tenth of a second with
nothing. For now `editorProcessKeypress()` just returns when that happens:

```
    if (read(fd,&ch,1) != 1) return; /* nothing typed in 0.1 s */
```

and `main()` calls it again, so kilo wakes ten times a second while you do
nothing. The timeout earns its place in the next lesson, where it is how
kilo tells the Escape key from the start of an arrow.

### The invariant: raw while kilo runs, as before after

The **invariant** is that the terminal is raw only while kilo runs, and is
put back exactly as it was whenever kilo ends itself. Three lines keep it.
`atexit(editorAtExit)` covers every call of `exit()`, normal or not:
`exit(1)` on an error puts the terminal back as surely as Ctrl-Q does.
`ISIG` off covers the keys that would end kilo without calling `exit()` at
all: a process killed by a signal runs no `atexit()` handlers, so with
`ISIG` on, Ctrl-C would leave nothing to put the terminal back. And the
check at the top of `enableRawMode()`

```
    if (E.rawmode) return 0; /* Already enabled. */
```

keeps a second call from saving the raw settings over `orig_termios`,
after which "putting the terminal back" would leave it raw.

`TCSAFLUSH` in `tcsetattr()` does one more small thing: the switch waits
for output already written, and throws away input typed before it, so a key
pressed while kilo was starting is not read as a command.

## Decide the boundary

kilo puts the terminal back with an `atexit()` handler and keeps the keys
that send signals for itself. A process can still die without running it:
`kill` sends SIGTERM, and a kilo killed that way leaves the terminal raw.
Another editor could also catch SIGTERM, SIGHUP and the rest and restore the
terminal in the signal handler, paying with code that runs inside a signal
handler, where very little is safe to call. Nothing can catch SIGKILL at
all. Which deaths are worth guarding against, when `stty sane`, typed even
blind, repairs the rest?

## Break it

Forget to put the terminal back. In `build/at/kilo/01.01/kilo.c`, in
`enableRawMode()`, delete the line

```
    atexit(editorAtExit);
```

<!-- verify: patch file=kilo.c
-    atexit(editorAtExit);
-->

and run it again with `./learn run kilo --at 01.01`. Press `a`, then
Ctrl-Q:

<!-- verify: session run="./learn run kilo --at 01.01" wait=2 send="a ctrl-q" more -->
```
97 ('a')
17
```

kilo exits as before, with status 0, but nothing put the terminal back:
echo, line editing, signals and output processing are all still off. Type
`ls` and Enter. Depending on your shell, what you type may not show at all
(bash) or may (zsh, which echoes for itself), but either way the output of
`ls` stair-steps: each line starts where the last one ended, because the
driver no longer turns `\n` into `\r\n`. Type `stty sane` and Enter, even if
you cannot see it, and the terminal is cooked again. Then put the line
back.
