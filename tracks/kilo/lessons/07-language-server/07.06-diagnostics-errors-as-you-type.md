# 07.06 Diagnostics: errors as you type

kilo keeps the list of problems the server finds in the text, underlines
each one on the screen, and says in the message line what is wrong where
the cursor is. Getting the underline under the right characters means
counting columns three ways.

## Where this fits

![Where 07.06 fits](figures/07.06-map.svg)

This lesson builds the diagnostics piece. The messages
piece hands it each list the server sends; it reads the list against the
copy of the text the sync piece keeps, and when the frame has drawn a row,
it draws the row's problems over it, underlined. It also reads where the
cursor is, to say the right message. After this lesson a C file shows its
errors as you type them, within half a second, without a save or a build.

## The idea

Since 07.05 clangd has answered every version kilo sent with a
**diagnostic** list, and kilo has dropped it. Delete the `a` of `total` in
the printf row of `sum.c` and the list that comes back holds an error. Each
diagnostic has a **range**, a start and an end, each a line and a
character counted from 0; a **severity**, 1 for an error, 2 a warning, 3
information, 4 a hint; and a message. Here the error is line 5, characters
16 to 20, `totl`, severity 1, "Use of undeclared identifier 'totl'; did you
mean 'total'? (fix available)", and then a blank line and a note. clangd
also sends the note as a diagnostic of its own: line 4, characters 5 to
10, the `total` of `int total`, severity 3.

Each list is all of the file's problems, so a new one replaces the last,
and an empty list means the file is clean. kilo keeps the list and does two
things with it.

It underlines each range. The frame has drawn the row already; after the
row, kilo goes back to its start with a carriage return, moves right to the
range with `ESC [ n C`, turns underlining on with `ESC [ 4 m`, writes the
range's characters again, and turns it off with `ESC [ 0 m`. The terminal
draws the same characters over themselves, now underlined.

And it says the message of the diagnostic on the cursor's row, cut to the
first line, in the message line: `6: error: Use of undeclared ...`, the
row counted from 1. Typing the error leaves the cursor on its row, so the
message shows as soon as the list arrives, with no other key. When a list
comes and the cursor's row has none, the line gives the counts instead if
they have changed: `lsp: 1 error, 1 info`, or `lsp: no problems`.

![sum.c with totl underlined, and total too, the message line saying the error on row 6. Beside it the publishDiagnostics message, trimmed: the error's range, line 5 characters 16 to 20, leads to the underline under totl](figures/07.06-screen.svg)

What a "character" counts is agreed in initialize. kilo offers two
**position encodings**, `"utf-8"` first, then `"utf-16"`, and the server
names the one it will use; with no answer it is UTF-16, the protocol's
default. In utf-8 a character is a byte of the line, which is how kilo
counts columns in a row already. In UTF-16 it is a **code unit**: one for
every character up to U+FFFF, two for one past it. clangd 21 answers
utf-8. And a tab before the range makes the column on the screen differ
again.

### `lspDiagnostics`

Takes a list: drops it if it is for another file (`lspPath()`,
`lspSameFile()`) or an older version; turns each range into bytes of the
copy's lines, clamped; keeps each message's first line; swaps the list in
with `lspSetDiagnostics()`, which holds the resize signal back meanwhile
(its handler draws rows); and says the cursor's diagnostic or the counts.

### `lspLine`

The bytes of one line of the copy. It finds where every line starts once
for each version of the copy, the first time it is asked.

### `lspColumn`

The server's character as a byte of that line, clamped to the line's end.
In utf-8 that is the number itself; in UTF-16 it walks the line a
character at a time, `lspCharLen()` telling how many bytes each takes.

### `lspPath`

A URI as a path, 07.05's `lspUri()` the other way round. Anything but a
`file://` URI with an absolute path, or one with a bad `%` escape or a
`%00`, is refused.

### `lspShowDiagnostic`

Says the diagnostic under the cursor, or else the row's first. A new list
calls it, and so does each pause, which says something only when the
cursor has come to another diagnostic.

### `lspDrawRow`

The underlines of one row, called once for every row the frame draws.

### `editorCursor`

In `kilo.c`, which alone can see `E`: the cursor's row and its byte in
that row. Outside these, the initialize request offers the encodings and
asks for diagnostics, and kilo notes the server's choice in `L.utf8`.

## How it works

### Three ways to count a column

![The printf row with two e's with an acute accent before totl, and three rulers under it: bytes, where totl starts at 23; UTF-16 units, 21; render columns, 30. The terminal's cells put it at 28](figures/07.06-columns.svg)

The server's number is in its encoding: bytes in utf-8, UTF-16 units
otherwise. kilo keeps every diagnostic in bytes of the row, the way the
cursor is kept, and converts once, when the list arrives:

```
while (i < len) {
    int n = lspCharLen(s+i,len-i), w = n == 4 ? 2 : 1;
    if (u+w > units) break;
    u += w;
    i += n;
}
```

A character of four UTF-8 bytes is the one that is past U+FFFF, so it is
the one that takes two units. When the row is drawn, the bytes become
render columns, the tab before them widened as 03.03 widens it:

```
for (k = 0; k < to; k++) {          /* bytes of chars to columns of render */
    if (k == from) a = b;
    b += chars[k] == '\t' ? 8-b%8 : 1;
}
```

And `ESC [ n C` counts cells, not bytes, so the last step leaves out the
bytes of render that continue a UTF-8 character (`0x80` to `0xBF`). To see
all three differ, make a copy of `sum.c` whose printf string starts with
two e's with an acute accent around a t (each e two bytes in UTF-8, C3 A9),
and `totl` already in it:

<!-- verify: session -->
```
$ printf '#include <stdio.h>\n#include "add.h"\n\nint main(void) {\n\tint total = add(2, 3);\n\tprintf("\303\251t\303\251: %%d\\n", totl);\n\treturn 0;\n}\n' > 'build/at/kilo/07.06/sam ple/accent.c'
```

Open it as above: `totl` is underlined where it is, and the message line
says `lsp: 1 error, 1 info`, since the cursor is on row 1. clangd 21 put
the error at characters 23 to 27; asked for UTF-16 only, it says 21 to 25.
Both are bytes 23 to 27, render columns 30 to 34, and kilo writes
`\r ESC[28C ESC[4m totl ESC[0m`: cells 28 to 31.

### Drawing over a finished row

![The bytes kilo writes for row 6: the row and ESC [ 0 K as before, then the second pass: \r, ESC [ 23 C, ESC [ 4 m, totl, ESC [ 0 m, and the row's \r\n](figures/07.06-drawn-over.svg)

The hook is one call in the frame, after the row and its `ESC [ 0 K`:

```
lspDrawRow(&ab,filerow,r->chars,r->size,r->render,r->rsize,
           E.coloff,E.screencols);
```

The core's code for a row is untouched. The price is that the second pass
knows nothing of how the first drew those characters. In the finished
project, with module 06's colours, `add(2, 3, 4)` gets "Too many arguments
to function call" on the `4`: the row draws it red, and the second pass
writes it again, underlined, in the default colour.

### What the server says is checked

```
if (version && jsonInt(version,-1) < L.version) return;
```

A list for a version older than the copy describes a text the server no
longer has, so it is dropped. Each range is clamped twice. When it is
stored: a line that is not in the copy drops the diagnostic, a character
past the line's end becomes the end, a range that ends before it starts
becomes empty, a severity outside 1 to 4 becomes 1. And when it is drawn,
against the row as it is now, which may be shorter than the copy's line if
you have deleted since the list came:

```
if (from > size) from = size;
if (to > size) to = size;
```

The **invariant** is that a stored diagnostic lies inside the copy's
lines; `lspColumn()` keeps it, returning -1 for a line the copy does not
have and the line's end for any column past it. Nor is the message
trusted. Only its first line is kept (clangd's carries its note after a
blank line), and every control byte is shown as `?` as it goes to the
message line: an `ESC [ 2 J` in a message would otherwise clear the screen.
Of a list of 1500, the first 1000 are kept and all are counted.

## Decide the boundary

kilo asks for utf-8 and still carries the UTF-16 conversion. With clangd
21 the conversion never runs; it is there for a server that ignores the
offer and counts in UTF-16, the protocol's default. Another client could carry one of the two: always UTF-16, which
works with every server and converts every position always, or only
utf-8, less code, and wrong by a column for each accented letter before a
range whenever a server does not agree to it. Which servers must it work
with?

## Break it

Count a tab as one column when the underline is placed. In
`build/at/kilo/07.06/lsp.c`, in `lspDrawRow()`:

<!-- verify: patch file=lsp.c
-            b += chars[k] == '\t' ? 8-b%8 : 1;
+            b += 1;
-->
<!-- verify: skip reason="the line as the reader changes it; the patch above makes the change" -->
```
            b += 1;
```

The build warns `unused parameter 'chars'`. Make the same error as in Run
it: the message line says the same thing, but the underlines are in the
wrong places:

<!-- verify: skip reason="rows of the editor's screen, underlines written out; captured on a 12 x 72 pseudo-terminal with track.py's Editor and clangd 21" -->
```
     [_:   in]t total = add(2, 3);
        printf("[_:%d\n]", totl);
```

The stored diagnostic is still bytes 16 to 20 of the row. Taken as render
columns 16 to 20, they leave out the seven columns the tab adds: the
underline lands seven columns left, on `%d\n`, which is drawn again in
place. On row 5, bytes 5 to 10 underline three of the tab's spaces and
`in`. Put the line back.

## Go deeper

- [The Language Server Protocol 3.17, Text Documents](https://microsoft.github.io/language-server-protocol/specifications/lsp/3.17/specification/#textDocuments) - why the protocol counts UTF-16: before 3.17 "the offsets were always based on a UTF-16 string representation", and it stays the only encoding a server must support; then [PositionEncodingKind](https://microsoft.github.io/language-server-protocol/specifications/lsp/3.17/specification/#positionEncodingKind), the three encodings, and [publishDiagnostics](https://microsoft.github.io/language-server-protocol/specifications/lsp/3.17/specification/#textDocument_publishDiagnostics): "Newly pushed diagnostics always replace previously pushed diagnostics."
- [Markus Kuhn's wcwidth.c](https://www.cl.cam.ac.uk/~mgk25/ucs/wcwidth.c) - how many cells a character takes: 0 for a combining character, 2 for the East Asian wide ones. kilo counts every character as one cell, so an underline after a wide character lands a cell left for each.
- [kitty's underline styles](https://sw.kovidgoyal.net/kitty/underlines/) - `CSI 4:3 m` for a curly underline and `CSI 58 ... m` for its colour, where a terminal has them; kilo sends `ESC [ 4 m`, the straight one.
