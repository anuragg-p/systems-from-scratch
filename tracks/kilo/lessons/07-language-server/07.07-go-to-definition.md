# 07.07 Go to definition

Ctrl-G asks the server where the name under the cursor is defined, and
moves the cursor there; if that is in another file, kilo reads that file
in place of this one. Ctrl-B goes back. It is the first question kilo asks
whose answer it has to act on, and it asks without stopping to wait.

## Where this fits

![Where 07.07 fits](figures/07.07-map.svg)

This lesson builds the definition piece, ask, then jump, second in the row
of the client's features, with an arrow up to the cursor. It reads where
the cursor is and, when the answer comes, moves it, through two small
functions the editor keeps for it. Its question and the answer go through
the messages piece below, and it uses the copy of the text to turn the
cursor's place into the server's numbers and back. After this lesson you
can follow a name to where it is defined, in this file or another, and
come back.

## The idea

Every message kilo has sent so far either needs no answer, or has one that
comes before kilo sends anything more: initialize at the start, shutdown
at the end. A question about the cursor is different. You press Ctrl-G whenever
you like, the answer comes some time later, between other messages such as
a list of diagnostics, and meanwhile you may have typed.

A request carries an **id**, and its answer the same id. So kilo sends
**textDocument/definition** with the next id, keeps that id, and goes back
to reading keys. When a message with no method and that id arrives, it is
the answer. Ask about `total` in the printf row of `sum.c`, the cursor on
its second `t`, byte 18 of the row:

<!-- verify: skip reason="a message from the editor's log of a run; checked by hand with clangd 21, the path shortened" -->
```
{"jsonrpc":"2.0","id":2,"method":"textDocument/definition","params":{"textDocument":{"uri":"file:///.../sam%20ple/sum.c"},"position":{"line":5,"character":18}}}
{"id":2,"jsonrpc":"2.0","result":[{"range":{"end":{"character":10,"line":4},"start":{"character":5,"line":4}},"uri":"file:///.../sam%20ple/sum.c"}]}
```

The answer is a **location**: a file, as a URI, and a range in it, here
the `total` of `int total` one row up. In the open file, kilo moves the
cursor to the range's start. In another file it has more to do, because
kilo holds one file at a time: it reads the other file in place of this
one, and tells the server, which has had this one open, that it is closed
and the other open. It does that only when nothing is unsaved, since
reading another file throws the rows away.

Before it moves, kilo remembers where the cursor was, one place only.
Ctrl-B goes there, and since Ctrl-B is a jump too, it remembers where it
came from: a second Ctrl-B goes forward again. And if you press any key
while the answer is still on its way, kilo forgets the question, and the
answer, when it comes, moves nothing.

![Ctrl-G and Ctrl-B on sum.c, a step at a time, each screen with its request or answer: Ctrl-G on total asks line 5 character 18, and the cursor goes to line 4 character 5, the total of int total; Ctrl-G on add asks line 4 character 14, and add.h opens with the cursor on add, line 1 character 18; Ctrl-B brings back sum.c; with an unsaved change, Ctrl-G on add says save first](figures/07.07-jump.svg)

### `lspDefinition`

Ctrl-G. With no server it says `lsp: no server`; with one that has not
answered initialize, `lsp: not ready`; with one whose answer did not offer
definitions, that it cannot find them. Otherwise it sends the text, if it
has changed, and then the request, keeping its id in `L.defid`.

### `lspUnits`

The cursor's byte as the server counts columns: 07.06's `lspColumn()` the
other way round.

### `lspDefinitionResult`

The answer, which the protocol lets be a location, a list of them (kilo
takes the first), a list of **location links** (a richer form, whose
`targetSelectionRange` is the name itself), or null. Anything kilo cannot
use says `lsp: no definition found`.

### `lspGoTo`

Remembers where the cursor is, switches files if it must, and moves the
cursor, the server's character turned into a byte with `lspColumn()`.

### `lspSwitch`

Another file: `editorJump()` reads it, then didClose for the old file,
didOpen for the new, version 1, and the old file's diagnostics forgotten.

### `lspBack`

Ctrl-B: `lspGoTo()` with the place remembered, or
`lsp: no place to go back to`.

### `editorJump`

In `kilo.c`, beside `editorCursor()`: reads another file in place of this
one, unless this one has unsaved changes or the other cannot be opened,
then moves the cursor, clamped to the file, and scrolls so it shows.
Outside these, `CTRL_G` and `CTRL_B` get their cases in
`editorProcessKeypress()`, the ready message names them, and the
initialize request asks for plain locations (`"linkSupport":false`).

## How it works

### The text goes first

In `lspDefinition()`, before the request:

```
lspSendText();
```

The position is counted in the text the server has. Type something and
press Ctrl-G within 300 ms, and the server's copy is the one before you
typed: the cursor's row and byte would point somewhere else in it. So
whatever the pause has not sent yet goes first, and the copy and the
position agree. With 07.05's script copied into this lesson's folder as
the server, the space typed before the last Ctrl-G above shows in the log
as a didChange, version 2, right before the third definition request.

### A key cancels

```
L.defid = 0;    /* a key cancels a jump still to come */
```

This is in `lspWaitKey()`, where a key has come in. Without it, an answer
that comes late would move the cursor while you are typing somewhere else,
and the next character would land there. With clangd the answers above
took 2 ms or less, so you cannot press a key in between; with a server
made to answer late, a key pressed meanwhile leaves the cursor where it is.
The **invariant**: `L.defid` is set only while a jump is still wanted.
`lspDefinition()` sets it; the answer clears it, as do a key and the
server's end.

### The answer is not trusted

![The answer's uri, file:///.../sam%20ple/add.h, its %20 decoded into the path's space; then what kilo does: no result, no definition found; the open file, move the cursor; another file, unsaved changes? save first; else open it](figures/07.07-uri.svg)

The URI goes through 07.06's `lspPath()`, so anything but a `file://` URI
with a clean absolute path is "no definition found", as is an answer of
the wrong shape. A line past the end of the file goes to its last row, and
a character past a line's end to the end. A file that cannot be read needs
care. `editorOpen()` exits kilo on an error other than "no such file", and
opens a missing file as a new, empty one. So `editorJump()` tries first:

```
if ((fp = fopen(path,"r")) == NULL) {
    editorSetStatusMessage("Can't open %s: %s",path,strerror(errno));
    return -1;
}
```

and only then frees the rows and calls `editorOpen()`, which replaces the
file's name and clears its modified flag. The server keeps running: one
server serves both files, the language taken from the new name. clangd
then publishes an empty list for the file closed; its URI is not the open
file's, so kilo ignores it. The status bar shows the path from the current
directory, `sam ple/add.h`. Ctrl-B goes through the same `editorJump()`,
so it too refuses to leave unsaved changes.

## Decide the boundary

kilo asks and carries on. The editor never freezes, whatever the server
does, but an answer can arrive at an awkward moment, so it must be
possible to cancel, and every place that acts on an answer must check that
it is still wanted. Another editor could ask and wait: send the request,
read the server until its answer comes, and only then take the next key.
That is far simpler, and the cursor can never move under you, but the
editor is frozen for as long as the server takes, and a server that never
answers freezes it for good. clangd answers here in a couple of
milliseconds, on a file of eight lines. How long can the answer take?

## Break it

Take the unsaved-changes check out of `editorJump()`. In
`build/at/kilo/07.07/kilo.c`, delete the four lines:

<!-- verify: patch file=kilo.c
-        if (E.dirty) {
-            editorSetStatusMessage("Unsaved changes: save first (Ctrl-S), then try again");
-            return -1;
-        }
-->
```
        if (E.dirty) {    <- delete these four lines
            editorSetStatusMessage("Unsaved changes: save first (Ctrl-S), then try again");
            return -1;
        }
```

Open `sum.c` as above. Press Down four times and Right fourteen times, onto
`add`, then Left and a space, as before, and Ctrl-G. `add.h` opens, and its
status bar says nothing about changes. Press Ctrl-B: `sum.c` is back, read
from the disk, `int total = add(2, 3);` with one space, and not
`(modified)`. Your edit is gone and nothing said so; Ctrl-Q quits at once,
with no warning, because as far as kilo knows there is nothing to lose.

`editorOpen()` sets the modified flag to 0 for the file it reads, which is
right for that file. The check was the only thing between the unsaved rows
and `editorJump()` freeing them. Put the lines back.

## Go deeper

- [The Language Server Protocol 3.17, Goto Definition](https://microsoft.github.io/language-server-protocol/specifications/lsp/3.17/specification/#textDocument_definition) - the request and its answer, `Location | Location[] | LocationLink[] | null`; and [LocationLink](https://microsoft.github.io/language-server-protocol/specifications/lsp/3.17/specification/#locationLink), whose `targetSelectionRange` is "the range that should be selected and revealed when this link is being followed, e.g the name of a function".
- [Hover](https://microsoft.github.io/language-server-protocol/specifications/lsp/3.17/specification/#textDocument_hover), [Find References](https://microsoft.github.io/language-server-protocol/specifications/lsp/3.17/specification/#textDocument_references) and [Completion](https://microsoft.github.io/language-server-protocol/specifications/lsp/3.17/specification/#textDocument_completion) - the same shape of question: each one's params extend `TextDocumentPositionParams`, a file and a position, as kilo sends here.
- [Cancellation](https://microsoft.github.io/language-server-protocol/specifications/lsp/3.17/specification/#cancelRequest) - `$/cancelRequest` asks the server to stop work on a request; it still answers, which is why kilo, which only forgets the id, ignores what comes.
