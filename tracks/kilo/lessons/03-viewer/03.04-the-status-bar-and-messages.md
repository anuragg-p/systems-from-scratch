# 03.04 The status bar and messages

The bottom two lines of the screen now belong to the editor itself: a status
bar in reverse video with the file's name, its length and the line the cursor
is on, and under it a line for short messages that go away on their own.

## Where this fits

![Where 03.04 fits](figures/03.04-map.svg)

This lesson builds the status bar, beside the frame on the map: two lines the
frame draws after the rows. It shows what the rest of the editor knows, the
file's name, how many lines it has and where the cursor is, and a message
that any part of the editor can leave for it. The file's text gives up two
rows of the screen to make room. After this lesson the editor says what it is
showing and where you are in it, and the later lessons have a place to tell
you things: a warning before quitting, how a save went, the search prompt.

## The idea

<!-- verify: mention names="hello.c" outside reason="a small C file the figure opens, not part of the project" -->

![hello.c on a 10 x 44 terminal: 8 rows of text, the status bar in reverse video on row 9, the message on row 10, and the bytes that draw those two lines.](figures/03.04-bars.svg)

At 03.03 you can move anywhere in `kilo.c`, but nothing on the screen says
which line you are on, how long the file is, or even which file it is. A
status bar does, on a line of its own at the bottom, and a message line under
it gives the editor somewhere to say things.

So the frame now has room for two rows fewer of text, `E.screenrows` is the
window's height minus 2, and after the rows come two more lines. The first
is the status bar, drawn in **reverse video**: `ESC [ 7 m` swaps the text and
background colours for everything written after it, and `ESC [ 0 m` puts them
back. On its left, the file's name, cut to 20 characters, and the number of
lines; at its right edge, the cursor's line and the number of lines, both
counting from 1; spaces in between, exactly as many as it takes for the
right part to end in the last column. For the figure's file, a six-line
`hello.c`, on 44 columns, that is `hello.c - 6 lines`, 17 columns, then 24
spaces, then `1/6`. The second line
is the message, shown if it was set less than five seconds ago. It is the
last line of the frame and has no `\r\n` after it, which is what the empty
bottom row has been waiting for since 02.01.

### The status bar and the message line, in `editorRefreshScreen`

After the last row of text: an erase, reverse video on, the left part made
with `snprintf` and cut to the screen's width, then spaces one at a time until
exactly the right part fits, the right part, reverse video off and `\r\n`.
Then, on the bottom row, an erase and the message, if it is fresh, cut to the
screen's width.

### `editorSetStatusMessage`

This takes a format and arguments as `printf` does, formats them into
`E.statusmsg`, 80 bytes, cut to fit, and notes the time in
`E.statusmsg_time`. main sets the first message before the first frame,
`HELP: Ctrl-Q = quit`, naming the one key so far that does anything besides
move.

## How it works

### The frame now fills the screen

The status bar's line ends in `\r\n`, and the message line ends with nothing:

```
    abAppend(&ab,"\x1b[0m\r\n",6);
```

With `E.screenrows` two less than the window, the rows of text and the status
bar take every row but the last, each ending in a newline, which leaves the
terminal's cursor at the start of the bottom row. The message is written
there, and the frame ends without a newline, so nothing scrolls. This is the
same rule as in 02.01, now with nothing wasted: the frame never sends a
newline on the bottom row. Break it removes the 2 and shows what happens
when the frame is two lines taller than the screen.

### Right-aligning the line number

The bar is padded one space at a time until the room left is exactly the
length of the right part:

```
    while(len < E.screencols) {
        if (E.screencols - len == rlen) {
            abAppend(&ab,rstatus,rlen);
            break;
        } else {
            abAppend(&ab," ",1);
            len++;
        }
    }
```

If the left part leaves less room than the right part needs, the room left
is never equal to its length, and the bar is the left part and spaces
only. A 25-character name on 32
columns shows `a-rather-long-file-n - 6 lines` and no line number; on 34
columns, `1/6` fits after it.

### A message goes only when something is drawn

The test for a fresh message is made while the frame is drawn:

```
    if (msglen && time(NULL)-E.statusmsg_time < 5)
```

and a frame is drawn only after a key, or a resize. So a message goes with
the first key pressed after it is five seconds old, never by itself. Measured:
six seconds without a key leave the help on the screen; the key pressed at
7.3 seconds draws a frame without it. `time()` counts whole seconds, so the
five seconds are between four and five, depending on where in a second the
message was set.

## Decide the boundary

kilo draws only when something happens: a key, or a resize. Yet it wakes up
ten times a second anyway, because raw mode makes `read()` give up after a
tenth of a second, and `editorReadKey` just reads again. An editor could
draw a frame on each of those wake-ups instead, and the message would go
after five seconds exactly, as would anything else that changes with time,
such as a clock. The price is a frame of around a kilobyte sent ten times a
second while nothing has changed, unless the editor also notices that
nothing has. kilo chooses a screen that changes only when you do something.
Is a message that outstays its five seconds a fault, or the price of a
quiet editor?

## Break it

Give the bars no room. In `build/at/kilo/03.04/kilo.c`, in
`updateWindowSize`, delete the line

<!-- verify: patch file=kilo.c
-    E.screenrows -= 2; /* Get room for status bar. */
-->
```
    E.screenrows -= 2; /* Get room for status bar. */
```

Make a file of numbered lines and open it:

<!-- verify: session host -->
```
$ printf 'line %d\n' $(seq 1 40) > build/at/kilo/03.04/lines.txt
```

```
./learn run kilo --at 03.04 -- lines.txt
```

<!-- verify: skip reason="a picture of the editor's full screen, from a 10 x 44 pseudo-terminal; verify cannot replay a full-screen program" -->
```
+--------------------------------------------+
|line 3                                      |
|line 4                                      |
|line 5                                      |
|line 6                                      |
|line 7                                      |
|line 8                                      |
|line 9                                      |
|line 10                                     |
|lines.txt - 40 lines                    1/40|
|HELP: Ctrl-Q = quit                         |

```

The file starts at line 3, though the bar says the cursor is on line 1 and
the cursor is on the top row. The frame now has 10 rows of text for a
10-row screen, then the status bar and the message: 12 lines, and the
newlines after the tenth row and after the bar both fall on the bottom row,
so the terminal scrolls up twice, and lines 1 and 2 are gone off the top.
Every frame is drawn the same way, two rows too high. Press Down ten times:
the bar says `11/40` and the cursor is drawn on the bottom row, over the
message, because the editor counts a row of text there that the screen does
not have. Put the line back.
