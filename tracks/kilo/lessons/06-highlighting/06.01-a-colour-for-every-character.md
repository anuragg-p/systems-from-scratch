# 06.01 A colour for every character

Each row of the file gets a second array beside its rendered text: one
highlight class for every character, worked out whenever the row changes and
read when the frame is drawn. This lesson builds that array, the table that
turns a class into a terminal colour, and the choice of a language by the
file's name. The one class it can show yet is the non-printable character;
the colours themselves start with 06.02.

## Where this fits

![Where 06.01 fits](figures/06.01-map.svg)

This lesson starts the highlight piece, on the right-hand side of the map
between render and the frame. Every time a row's rendered text is made, the
highlighter goes over it and gives each of its characters a class; when the
frame is built, it reads those classes and draws each character the way its
class says. The piece also keeps the table of languages kilo knows, and
picks one from the file's name before the file is read. The rows, the edits
and the search work as they did in the core, and a file kilo has no language
for is drawn exactly as before. After this lesson a C file shows a control
character as a letter in reverse video, one cell wide, instead of sending
the raw byte to the terminal.

## The idea

The core sends each row to the terminal as its bytes, and the terminal draws
them all in one colour. To draw `return` in yellow, kilo has to send
`ESC [ 33 m` before it and `ESC [ 39 m` after it, which a terminal reads as
"yellow from here" and "the default colour from here". So while it builds
the frame, kilo has to know, character by character, what each one is.

It keeps that in the row. Beside `render` each row now has `hl`, an array as
long as `render`, holding one **highlight class** for each byte: a small
number that says what the character is. Class 0, `HL_NORMAL`, is ordinary
text; class 1, `HL_NONPRINT`, a byte the terminal has no picture for, such
as the 1 that Ctrl-A types. Later lessons add more. The classes are worked
out where `render` is made, so `hl` is never older than the text. Drawing a
row is then a walk along it a byte at a time: the colour of the byte's
class, an escape code only where the colour changes, then the byte.

Which class a character gets depends on the language: `//` starts a comment
in C and means nothing in a text file. So kilo keeps a small database of
languages, `HLDB`, with one entry, C and C++, chosen when the file's name
ends in `.c`, `.h`, `.cpp`, `.hpp` or `.cc`. A file with no language gets
class 0 everywhere, and is drawn byte for byte as the core draws it.

At this lesson the scanner knows one class besides 0. Here is Ctrl-A typed
at the same place in `countdown.c`, the twelve-line C program this module
uses, and in a copy of it named `countdown.txt`. In the C file it takes one
cell, so the cursor, which counts bytes, stays on its character:

![The same keys in countdown.c and countdown.txt at 06.01: in the C file the byte Ctrl-A typed is a reverse-video A, one cell wide; in the text file the terminal draws nothing for it, and the cursor is drawn on the < instead of the space](figures/06.01-two-files.svg)

![Row 4 with a Ctrl-A in it: each byte of render has a class in hl, and the frame sends an escape code only where the class changes. Below, the classes this module brings, the colour editorSyntaxToColor() gives each, and the lesson that brings it](figures/06.01-hl.svg)

### `editorUpdateSyntax`

This makes `hl` for one row. It grows `hl` to `rsize` bytes and fills it
with 0, and stops there if the file has no language. Otherwise it walks
`render`, skipping the spaces at the start, and marks each byte that
`isprint()` says no to as `HL_NONPRINT`. The walk is a skeleton the next
three lessons fill in: each adds its rule ahead of the last line, "anything
else stays normal". It is called from one place, the end of
`editorUpdateRow()`.

### `editorSyntaxToColor`

The table from a class to a colour: the number n of `ESC [ n m` that sets
the text colour. Here it has only its default, 37 (white), which nothing
reaches yet: classes 0 and 1 are drawn without it. Each later lesson adds a
case for its class.

### `editorSelectSyntaxHighlight`

This picks the language from the file's name. For each language in `HLDB`
and each of its patterns in `filematch`, it sets `E.syntax` at the first
that fits, and returns. A pattern that starts with a dot must end the name;
any other may be anywhere in it. `main()` calls it with the name before
`editorOpen()` reads the file, because each row is highlighted as it is
read.

### Drawing a row, in `editorRefreshScreen`

Where the core sent a row with one `abAppend()`, the frame now sends it a
byte at a time, with `current_color` holding the colour set last (-1: the
default). A class 1 byte goes out as `ESC [ 7 m` (reverse video), a letter
(`'@'` plus the byte, for 1 to 26) or `?`, then `ESC [ 0 m` (all off). A
class 0 byte goes out as it is; any other in its class's colour.

Outside these functions: the `hl` field of a row (NULL for a new row, freed
with it), `struct editorSyntax` with its one field so far, the `HLDB` table,
`E.syntax`, and the two classes' `#define`s.

## How it works

### One class for every byte of render

The **invariant** this lesson adds is that `hl` holds exactly `rsize`
classes, one for each byte of `render`, never older than it. Two lines keep
it, at the top of `editorUpdateSyntax()`:

```
row->hl = realloc(row->hl,row->rsize);
memset(row->hl,HL_NORMAL,row->rsize);
```

and one call, the last line of `editorUpdateRow()`:

```
editorUpdateSyntax(row);
```

Every change to a row's text already ends in `editorUpdateRow()`, because
`render` must follow `chars` (03.03), so hanging the highlighter on that call
keeps `hl` in step with no new code in any edit. And `hl` follows `render`,
not `chars`: a tab is one byte of `chars` but up to eight of `render`, each
with a class, so the frame reads `render[j]` and `hl[j]` with the same `j`.
The frame never checks; it trusts the invariant, and draws from the classes
alone, as Break it shows.

### A colour sent only where it changes

```
if (current_color != -1) abAppend(&ab,"\x1b[39m",5);
```

The frame goes back to the default colour at the end of a row only if the
row left another one set. antirez's kilo sends `ESC [ 39 m` after every
row, which makes the bytes for a file with no language differ from the
core's. Here they are the same: `countdown.txt` with the keys above gives
the same bytes at 05.02 and at 06.01, checked byte for byte.

### One cell for each byte, and a signed char

```
if ((unsigned char)c[j] <= 26)
    sym = '@'+c[j];
else
    sym = '?';
```

A non-printable byte is always one cell, because the cursor code of 03.03
counts one screen column per byte. antirez's kilo tests `c[j] <= 26`. C
leaves it to the compiler whether `char` is signed, and on this Mac it is:
a byte above 127 is negative, passes, and `'@'+c[j]` is not a letter. Put
that line back and type an e with an acute accent into a C file: UTF-8
sends the bytes 0xc3 0xa9, and kilo sends the terminal 0x03, another
control character, and 0xe9, half of a character, where the cast gives
`??`.

After the reverse video, `current_color = -1`: `ESC [ 0 m` turns the colour
off too, so the next coloured byte must send its colour again. Nothing is
coloured yet; from 06.02 on, the original draws such a run without its
colour.

### Every place the pattern is

<!-- verify: mention names="my.cool.c" outside reason="a file name used as an example, not a file of the project" -->

The original looks for a pattern only where it first appears in the name,
`if ((p = strstr(filename,s->filematch[i])) != NULL)`. In `my.cool.c` that
is the start of `.cool`, not the end, so antirez's own build opens it with
no language (checked: a Ctrl-A in it does not show). The loop here tries
each place, and the last `.c` ends the name.

## Decide the boundary

kilo decides the language from the file's name, once, before it reads the
file. It is cheap, it never changes while you type, and it is wrong
whenever the name is: a C file saved as `notes`, a backup named
`countdown.c.orig`. Another editor could look inside the file too, at a
first line such as `#!/bin/sh`, or a comment that names the language, and
let you choose by hand. It pays with rules that can disagree, and a
language that changes while you edit the first line. Is a file's name, or
its first line, the better witness to what is in it?
