# 06.07 File system calls

This lesson covers the system calls that turn a path and a set of flags
into a file descriptor: `open`, and the `create` it shares with `mkdir`
and `mknod`.

## Where this fits

![Where 06.07 fits](figures/06.07-map.svg)

The file system calls are where the storage stack of module 05 meets user
programs. Above them is every program that opens, creates or names a file,
and the shell's redirection, which is built on how descriptors are
numbered. Below, they use path lookup, directories, inodes, the log and
open files from module 05. After this lesson a program can create, open
and name files by path, and the whole road from a command typed at the
shell down to a block on the disk is in place.

## The idea

![Redirection with `cmd > f`: after `close(1)` the lowest free slot is 1, so `open` puts the file there.](figures/06.07-lowest-fd.svg)

**The need.** A program calls `open("a", O_WRONLY|O_CREATE|O_TRUNC)` and
wants back a small number to pass to `write`. Behind that one call the
kernel has to find the file by its path, or make it, with an inode and a
directory entry; check that it may be opened that way; empty it if asked;
wrap it in an open file; and give the process a number for it.

**The idea.** A **file descriptor** is just an index into the process's
own array of 16 open-file pointers, and `open` always uses the lowest
free index. Opening is then three steps: find or create the inode, all
inside one log transaction; make an open file for it with the right
permissions and offset 0; put that in the lowest free slot.

"Lowest free" sounds like a detail, but the shell's redirection is built
on it. To run `echo hi > f`, the shell's child closes descriptor 1 and
then opens `f`. The lowest free slot is now 1, so `f` lands there, and
`echo`, which writes to descriptor 1 as always, writes into the file
without knowing.

### `fdalloc`

Every call that hands out a descriptor goes through it: `open`, `dup`,
`pipe`. All three come with this lesson, and so do the other calls that
work on names: `link`, `unlink`, `mkdir`, `mknod` and `chdir`.
`kernel/sysfile.c:fdalloc(f)` puts an open file in the lowest free slot of
the process's table and returns the index, or -1 if all 16 are taken.

### `create`

Where every new name is born: `open` with `O_CREATE` makes a file with it,
`mkdir` a directory, `mknod` a device.
`kernel/sysfile.c:create(path, type, major, minor)` finds the parent
directory, returns the existing inode if a plain file of that name is
already there, and otherwise allocates an inode, gives a directory its `.`
and `..`, and links the name into the parent. It returns the inode locked.

### `sys_open`

The `open` system call. `kernel/sysfile.c:sys_open` reads the path and
flags, finds or creates the inode, refuses to open a directory for
writing, makes an open file and a descriptor for it, empties the file if
`O_TRUNC` was given, and returns the descriptor.

### `sys_pipe`

The call that makes a pipe. It gets the two open files from `pipealloc`
(06.06), gives each a descriptor, and copies the two numbers out into the
array the program passed. If a descriptor or a copy fails, it takes back
the slots it filled and closes both files, so a failed `pipe` leaves the
process as it was.

### `sys_dup`

A second descriptor for an open file the process already has: the lowest
free slot, pointing at the same open file, whose count goes up by one
(05.07). Both descriptors share one offset. With `close`, it is the other
half of redirection: the shell will use it to move a pipe's end onto
descriptor 0 or 1.

### `sys_mkdir` and `sys_mknod`

Both are `create` with another type. `mknod` makes a **device file**: an
inode with no data, only a device number. Opening it gives an open file that reads and writes through the device table (05.07)
rather than disk blocks, so a program can reach the console by a name.
The disk `mkfs` builds has none; the first program will make one called
`console` (07.02).

### `sys_chdir`

Sets the directory that relative paths start from, the process's current
directory. It checks that the new path is a directory, then lets go of
the old one with `iput` inside the transaction: if that directory was
removed while it was still current, this is its last reference, and
`iput` frees it on disk.

## How it works

### Writing `create`, step by step

1. **A new plain file under a name that is free:** find the parent
   directory (`nameiparent` also leaves the path's last element in
   `name`, 05.06), allocate an inode with one link, and enter the name:
   ```
     if((dp = nameiparent(path, name)) == 0)
       return 0;
     ...
     if((ip = ialloc(dp->dev, type)) == 0){
     ...
     ip->nlink = 1;
     iupdate(ip);
     ...
     if(dirlink(dp, name, ip->inum) < 0)
       goto fail;
     ...
     return ip;
   ```
2. **Fail if the parent has been removed** since `nameiparent` found it:
   a name added there would go when the directory is freed, and leave its
   inode allocated with no name at all.
   ```
     if(dp->nlink == 0){   // the directory was removed after nameiparent
       iunlockput(dp);
       return 0;
     }
   ```
3. **If the name exists:** for `open` with `O_CREATE` on a file or device,
   that is fine, so return it locked; anything else fails, such as `mkdir`
   of a name that is taken.
4. **For a directory, add `.` and `..`,** and count the `..` in the
   parent's link count only after the name is linked, when nothing can
   fail any more.
5. **On failure, set the new inode's link count to 0** and let go of it,
   so the ordinary release path frees it.

### Writing `sys_open`, step by step

1. **Open an existing file:** copy the path in, and inside one log
   operation look it up, lock it, wrap it in an open file with a
   descriptor, unlock it and return the descriptor:
   ```
     begin_op();
     ...
       if((ip = namei(path)) == 0){
       ...
       ilock(ip);
     ...
     if((f = filealloc()) == 0 || (fd = fdalloc(f)) < 0){
     ...
     iunlock(ip);
     end_op();
     return fd;
   ```
2. **`O_CREATE` goes through `create`** instead of `namei`, and gets the
   inode back already locked.
3. **Refuse what cannot be opened that way:** a directory for anything but
   reading, and a device file whose number is outside the device table.
   That number comes from the disk, where it could be anything, and it is
   used as an index into the table.
4. **If the descriptor fails, give back the open file:**
   ```
     if((f = filealloc()) == 0 || (fd = fdalloc(f)) < 0){
       if(f)
         fileclose(f);
   ```
5. **Set the permissions from the flags, and truncate if asked.**

### Writing `sys_link`, step by step

`link(old, new)` gives an existing file a second name.

1. **Count one more name, then add it.** Find the file, raise its link
   count, and enter `new` in its parent directory with the same inode
   number:
   ```
     if((ip = namei(old)) == 0){
     ...
     ip->nlink++;
     iupdate(ip);
     iunlock(ip);
     if((dp = nameiparent(new, name)) == 0)
       goto bad;
     ilock(dp);
     ...
     if(dp->dev != ip->dev || dirlink(dp, name, ip->inum) < 0){
     ...
     iput(ip);
   ```
2. **Count first, and unlock the file before locking the directory.**
   Raised first, the count is never lower than the number of names that
   point at the inode, not even for a moment. And holding `d/a` while
   locking `d` would deadlock against an `unlink("d/a")`, which locks `d`
   and then `a`.
3. **No links to directories.** A directory with two parents would make
   `..` ambiguous and could close a loop in the tree.
4. **Undo on failure:** a parent that does not exist, one removed since
   `nameiparent` found it, where the name would go with the directory, or
   one on another device, where the inode number means nothing, takes the
   count back down.

### Writing `sys_unlink`, step by step

1. **Find the entry in the parent, zero it, count one name fewer:**
   ```
     ilock(dp);
     ...
     if((ip = dirlookup(dp, name, &off)) == 0)
       goto bad;
     ilock(ip);
     ...
     memset(&de, 0, sizeof(de));
     if(writei(dp, 0, (uint64)&de, off, sizeof(de)) != sizeof(de))
       panic("unlink: writei");
     ...
     ip->nlink--;
     iupdate(ip);
   ```
   The inode is not freed here. When its count reaches 0, the last `iput`
   frees it, so a process that still has the file open keeps reading it.
2. **Never `.` or `..`:** removing them would leave a directory with no
   way back up.
3. **A directory must be empty.** `isdirempty` looks past the first two
   entries for any slot still in use; removing a full directory would
   leave its files allocated and unreachable.
4. **A removed directory takes its `..` with it,** so the parent's link
   count goes down by one too.

### Why it is built this way

**One transaction for the whole open.** `sys_open` calls `begin_op` before
it looks anything up and `end_op` just before it returns. Creating a file
writes an inode and a directory entry, and maybe a directory's link count
too; inside one transaction they reach the disk together or not at all
(05.04).

**`create` cleans up by forgetting.** If anything fails after the inode is
allocated, for example the parent directory cannot grow, `create` sets the
new inode's link count back to 0 and lets go of it. An inode with no names
and no users is freed by the ordinary release path, so there is no special
undo code.

**Link counts for directories.** A directory's link count is its own name
plus the `..` entry of each subdirectory, which is why making a directory
adds one to its parent's count. The new directory's `.` is not counted:
it points at itself, and a count that included it could never reach 0.

![Two names for inode 16, a new file on the 07.03 disk: `link` and `unlink` move `nlink`, and the inode is freed only when it reaches 0 and no file has it open.](figures/06.07-nlink.svg)

**Truncating is separate from creating.** `O_TRUNC` empties the file;
`O_CREATE` only makes it exist. The shell's `>` (07.02) will pass both;
its `>>` passes `O_CREATE` without `O_TRUNC`, and since this kernel has no
append mode, the offset still starts at 0: `echo x >> c` on a file
holding `hello` overwrites the first two bytes and leaves `x`, a newline
and `llo`.

**Unlock, keep the reference.** `sys_open` returns with the inode unlocked
but still referenced by the open file. A process may keep a file open for
as long as it runs; holding the inode's lock all that time would freeze
every other user of the file. The lock is taken again only for each read
or write.

The **invariant**: a descriptor is always the lowest slot that was free at
the moment it was handed out. No call ever says "give me descriptor 1";
`close` and `dup` plus this rule are the whole mechanism.

## Break it

No program opens anything until there is a first process, so this
experiment uses the 07.02 build. That first program, `init`, sets up the
console before anything else: it opens `console` (making the device file
with `mknod` first if the open fails, as it does on a fresh disk), calls
`dup(0)` twice so that descriptors 1 and 2 name the same open file, and then
prints `init: starting sh`.

In `build/at/xv6/07.02/kernel/sysfile.c`, make `fdalloc` search from the
top: replace `for(fd = 0; fd < NOFILE; fd++)` with
`for(fd = NOFILE-1; fd >= 0; fd--)`. Run `./learn run xv6 --at 07.02`. The
kernel starts all harts and then prints nothing more:

<!-- verify: patch file=kernel/sysfile.c at=07.02
-  for(fd = 0; fd < NOFILE; fd++){
+  for(fd = NOFILE-1; fd >= 0; fd--){
-->
<!-- verify: session run="./learn run xv6 --at 07.02" hangs=5
lines 3-4 unordered
-->
```
xv6 kernel is booting

hart 2 starting
hart 1 starting
```

`init`'s open got descriptor 15 instead of 0. `dup(0)` fails because slot 0
is empty, so 1 and 2 stay empty too, and `init: starting sh` goes to a
descriptor that does not exist. The shell it starts has no input either:
its first read fails, it takes that as end of file and exits, and `init`
starts another, over and over. Control-P a few seconds in shows the
newest process's pid already in the thousands, and still climbing:

<!-- verify: session send=ctrl-p
line 1 ~ 1 (sleep |runble|run   ) init
line 2 ~ [1-9]\d{3,} [a-z]+ +(init|sh)
line 2 optional
-->
```
1 sleep  init
1856 run    init
```

One wrong promise in `fdalloc` takes the console away from every process.

## Decide the boundary

<!-- verify: mention names="dup2(old, new)" outside reason="a call of other kernels (Unix, Linux), not this one's" -->
xv6 hands out the lowest free descriptor and lets user code rearrange the table with
`close` and `dup`. That makes redirection a few lines of user code and no special
kernel support. Another kernel could return an opaque handle (Windows does) and add a
call like `dup2(old, new)` or a spawn call that takes a descriptor map, so that the
child's table is built explicitly rather than as a side effect of the allocation order.
It would pay with a bigger interface. Linux keeps the xv6 rule and adds `dup2`/`dup3`
and `O_CLOEXEC` for the cases the rule makes awkward. Is "lowest free" a convenience
the kernel offers, or a contract every program quietly depends on?
