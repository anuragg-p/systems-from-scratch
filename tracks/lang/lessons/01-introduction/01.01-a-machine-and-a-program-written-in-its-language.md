# 01.01 A machine, and a program written in its language

A processor runs **instructions**, and the first programs were written as
nothing else. This lesson builds a small machine, a C program that runs RISC-V
instructions written as text, and one program for it written by hand: the
greatest common divisor of two numbers. Every way of running a program that
this chapter builds ends in a machine, so the track starts with one.
**Read first:** chapter 1 from its first page to the start of section 1.1 (pages 5 to 7), in Programming Language Pragmatics, 4th edition.

Example 1.2 shows that program as assembly; this lesson writes it for a
machine of your own (Example 1.1, the bytes, comes in lesson 01.02). The
book's examples are in C and x86 assembly; this track's are in a language of
your own and in RISC-V.

3. **By a translator** (01.04): the translator makes a C program of it, and

## The idea

![The machine: a few registers, a program, and the rule for which instruction runs next.](figures/01.01-machine.svg)

Before a program in any language can run, something has to run instructions.
This track builds its own: `machine`, a C program that behaves as a RISC-V
processor would, and runs a program written as assembly text.

A machine is three things. **Registers**: a few named places, each holding one
number; this one has RISC-V's 32, of 64 bits each, named `zero`, `ra`, `sp`,
`a0`, `s1` and so on. A list of **instructions**, each a small step: `sub s1,
s1, s2` subtracts `s2` from `s1` and leaves the result in `s1`. And a rule for
which runs next: the next in the list, unless the one that just ran was a
**jump**, or a **branch** (a jump taken only when a comparison holds).
**Assembly** is that list as text, an instruction a line; a **label** such as
`loop:` names the place of the instruction after it, so that a jump can say
where it goes. Here is `programs/gcd.s`:

```
# gcd.s: the greatest common divisor of two numbers, written by hand
# for the machine. i is kept in s1 and j in s2.
main:
    call getint           # a0 = the next number of the input
    mv   s1, a0           # i
    call getint
    mv   s2, a0           # j
loop:
    beq  s1, s2, done     # until i == j:
    ble  s1, s2, smaller  #   the larger one loses the smaller
    sub  s1, s1, s2       #   i = i - j
    j    loop
smaller:
    sub  s2, s2, s1       #   j = j - i
    j    loop
done:
    mv   a0, s1
    call putint           # print i
    li   a0, 0
    call exit             # status 0
```

`call getint` puts the next number of the input in `a0`, and `mv` copies it:
`i` lives in `s1`, `j` in `s2`. In the loop, `beq` leaves when the two are
equal, and `ble` (branch if less or equal) goes to the other arm when `s1` is
the smaller; each arm subtracts and jumps back. At `done`, `call putint`
prints `a0`, and `call exit` ends the program with status 0.

<!-- verify: fact cmd="grep -cE '^ +[a-z]' programs/gcd.s" expect=14 -->
Writing it by hand made you decide everything, in 14 instructions: that `i` is
`s1`, every label, and where each jump goes (`ble` to `smaller`, not to
`loop`, or the program is wrong without a word). The `if` and `else` are two
branches and two jumps that nothing in the text names. And it runs on this
machine only: the book's case for languages above the machine.

The text is real RISC-V, which the GNU assembler takes as it is. Its `mv` and
`call` are **pseudo-instructions**, shorthands for one and two real ones; this
machine counts each as one, and runs the text where a real processor runs
numbers. Chapter 5 gives it numbers.

### `find_labels`, `read_instructions` and `reg`

The first pass, `find_labels`, splits the file into lines and cuts each at its
comment; it records each label with the address the next instruction will
have, and keeps the rest of the line as an instruction's text. The second,
`read_instructions`, finds each name in `ops[]`, where a short string says
what follows it: `rrr` three registers (`sub`), `rrl` two registers and a
label (`beq`), `rn` a register and a number (`li`). One loop reads every
instruction's operands from that string; a label becomes its address, and a
`call` may name one of the machine's routines instead. `reg` looks a register
up among the 32 names in `regs[]`, which are in RISC-V's order, `zero` x0 and
`ra` x1: where a name is found is its number.

### `getint` and `routine`

`routine` does in C what `getint`, `putint` and `exit` stand for, changing
`a0` and nothing else. `getint` adds the digits up in an `unsigned long`, so a
number too large for 64 bits wraps around instead of being undefined in C; at
the end of the input it stops the program with status 1.

### `run` and `trace`

`run` starts at `main` with `pc`, the **program counter**, the address of the
next instruction. Each time round it checks `pc`, counts the instruction,
copies the registers into `before[]` for `trace`, and does what the `switch`
says; a jump, or a branch whose comparison holds, sets the next `pc`. Sums are
done on unsigned numbers, which wrap around as RISC-V's registers do, and
`div` by zero gives -1, as RISC-V's does.

## How it works

### A jump forward needs a second pass

Line 9, `beq s1, s2, done`, names a label seven lines further down: read in
one pass from the top, the machine would meet `done` before it knew where
`done` was. So the first pass only counts. A RISC-V instruction is 4 bytes, so
instruction `i` is at address `4 * i`, and a label's address is 4 times the
number of instructions above it:

```
      labels[nlabels++] = (Label){p, len, 4L * ninsns};
```

### The way back is an address in a register

`call` puts the address of the next instruction in `ra` and goes to the label;
`ret` goes to the address in `ra`. In the trace, `ra = 4` after the first
`call` is line 5's `mv`, and 56, after the last, is 14 times 4. At the start
`ra` holds 56, the address just past the last instruction, so a
`main` that calls nothing can end with `ret`, and the program stops, as a C
`main` returns to whoever called it. `gcd.s` calls `getint`, which replaced
`ra`: a `ret` on its last line would go back to line 19, after the last call,
and run lines 19 and 20 for ever. So it ends with `call exit`.

### The library is part of the machine

`getint`, `putint` and `exit` are not labels in `gcd.s`; the second pass finds
them among the machine's routines. A real processor has no such instructions:
reading a number is code, which asks the operating system for characters, kept
in a library and joined to each program by the linker. Lesson 01.02 writes it
in C, in `rt.c`, and lesson 01.04 links it (the book's Example 1.11). Here it
is the machine's, so that a program of this chapter reads and prints in one
line, and the machine needs no memory or operating system.

### One register is always 0

The **invariant** of the machine: `zero` always holds 0. A program may name it
as the register to write, and the write is dropped. Every instruction writes
its register through one function, and this line keeps it:

```
  if (r != ZERO)                 // what is written to zero is dropped
    x[r] = v;
```

With it, 0 is always to hand. The real assembler's `beqz a0, done` is `beq a0,
zero, done`, and its `j loop` is a jump-and-link (`jal`) that writes its
return address into `zero`: nowhere.

## Decide the boundary

This machine keeps the program as text, in C structs that nothing the program
does can reach. A real RISC-V computer keeps it as numbers, 4 bytes an
instruction, in the same memory as its data, and fetches each instruction
from there by its address. That buys a great deal: a program is only bytes,
so another program can write it and load it, which is how every compiler's
output comes to run. It costs an encoding, a decoder and a memory with
limits, none of which says anything about languages; chapter 5 pays it. Does
your machine need to run a program that another program has just made?

## Break it

Make the machine read the file once. In `build/at/lang/01.01/machine.c`, in
`read_instructions`, let an instruction see only the labels that a single pass
from the top would have met: after the line that finds the label, add

<!-- verify: patch file=machine.c
         Label *l = find(p, n);
@block
-->
```
        if (l && l->address > 4L * i)
          l = NULL;
```

A label further down has an address greater than the instruction's own, and is
now treated as missing. Build it again and run:

<!-- verify: session -->
```
$ make -s
$ ./machine programs/gcd.s < programs/gcd.in; echo $?
machine: programs/gcd.s:9: no label 'done'
1
```

Line 9 is the first jump forward, and `done` is in the file, seven lines down.
An assembler that reads once must forbid jumps forward, or remember each one
it cannot finish and fill it in when the label turns up; reading twice is the
simplest of the three. Take the two lines out again.
