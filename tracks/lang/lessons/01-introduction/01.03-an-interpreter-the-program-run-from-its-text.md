# 01.03 An interpreter: the program run from its text

The first way to run a program of your language: an interpreter that reads
the program's text and does what each line says, a line at a time, with
nothing worked out in advance. With it every program of your language runs.
Its cost, every line read again on every pass of a loop, is what the rest of
the chapter works against.
**Read first:** section 1.4 up to and including Example 1.10 (pages 17 to 19), in Programming Language Pragmatics, 4th edition.

Example 1.8 is this arrangement: an interpreter that stays in charge while
the program runs, with the program as its data. Example 1.10's early Basics,
with no first pass to strip the comments out, are this interpreter exactly,
and Run it measures what the book says that cost them.

## The idea

![An interpreter stays: the program's text and its input go in together, and the interpreter is what runs.](figures/01.03-stays.svg)

A program of your language is text, so the most direct way to run it is to
read a line, do what it says, and find the next line. `mote0` holds three
things: the program's lines, the number of the line it is on, and a table of
names with their values. To run a line it reads the line's characters. The
first word says what kind of statement it is; an expression is worked out
from its characters as they are read. Nothing is prepared, and nothing is
remembered about the text. A loop's lines are read again on every pass, and
a name is found by comparing its characters with each name in the table,
every time it is used.

Take `i := i - j` in gcd's loop. The first word, `i`, is not a keyword, so
it is an assignment; after the `:=` the expression is read: the characters
`i` are looked up in the table, then `-`, then `j` is looked up, and the
difference is worked out. Then `i` is looked up a third time, to store it.
The next pass does all of it again. This is the interpreter that stays, in
section 1.4's words: while the program runs, `mote0` is what runs, and the
program is its data.

### `split` and `run`

`split` cuts the file into lines, once. `run` goes through them a line at a
time and looks at each line's first word. A `while` or an `if` works out its
condition from the text; when it holds, the block is entered and `open[]`
remembers it: for a `while` the line to come back to, for an `if` -1. When
it does not, `skip` reads forward to the block's end. An `end` of a `while`
goes back to the `while`'s line, whose condition is read again. An `else`
reached after the `then` part has run reads forward to its `end`.

### `statement` and `input`

A line that is not a block is `read`, `write` or an assignment, by its first
word. Each checks that nothing is left on the line before it does anything;
in `x := e`, `e` is worked out before `x` gets the value. `input` reads a
number exactly as the machine's `getint` does.

### `factor`, `term`, `expr` and `cond`

One pointer, `p`, moves over the line's characters. `expr` adds and
subtracts `term`s, `term` multiplies and divides `factor`s, and a `factor`
is a number, a name's value, a minus and a factor, or an expression in
parentheses: one function for each level of precedence, so `*` is done
before `-`. Division by zero is an error, at the line. `cond` compares two
expressions, looking for `<=` before `<` so as not to stop at the first
character.

### `find` and `set`

The table of names is a list. `find` compares a name's characters with each
entry; `set` gives a name a value, adding it to the list the first time.

### `skip`

Reading forward to the `end` that closes a block, looking only at each
line's first word. How it finds the right `end` is below.

## Run it

<!-- verify: session wait=10 -->
```
$ ./learn run lang --at 01.03
Running lang as it stands at 01.03 (An interpreter: the program run from its text). Its files are in build/at/lang/01.03/
21
```

That is `./mote0 programs/gcd.mote < programs/gcd.in`: your language's first
program, run. `--count` prints how many lines `mote0` read to run it, on the
error output:

<!-- verify: session -->
```
$ cd build/at/lang/01.03
$ ./mote0 --count programs/gcd.mote < programs/gcd.in
21
88 lines read
$ ./mote0 --count programs/sum.mote < programs/sum.in
5050
409 lines read
$ ./mote0 --count programs/primes.mote < programs/primes.in > /dev/null
844 lines read
```

`gcd.mote` is 11 lines, and 88 are read. Each of the 11 passes of the loop
reads all seven of its lines, 4 to 10, whichever arm runs: the other arm's
lines are read to skip them. When the loop ends, the `while` line is read
once more and the six lines below it are read past. Three lines before the
loop, 77 in it, 7 to leave it and the `write`: 88.

![mote0 on gcd.mote with 6 and 4: the line it reads at each step and the table of names. The loop's lines are read again on every pass.](figures/01.03-reread.svg)

A comment costs the same. Make a copy of `gcd.mote` with a comment line
inside the loop, and count again:

<!-- verify: session -->
```
$ { head -4 programs/gcd.mote; echo '    # one more line in the loop'; tail -n +5 programs/gcd.mote; } > comment.mote
$ ./mote0 --count comment.mote < programs/gcd.in
21
100 lines read
```

Twelve more: once on each of the 11 passes, and once when the loop is read
past. That is the book's remark about comments in early Basics, made exact:
with nothing done to the text before the run, a comment is read every time
the loop goes round.

A mistake is found when its line runs, and reported with the file and the
line. A name used before anything gives it a value, and a division by zero:

<!-- verify: session -->
```
$ printf 'write 1\nx := y + 1\n' > late.mote
$ ./mote0 late.mote; echo $?
1
late.mote:2: y has no value yet
1
$ printf 'read a\nb := 0\nwrite a / b\n' > zero.mote
$ echo 5 | ./mote0 zero.mote; echo $?
zero.mote:3: division by zero
1
$ printf 'if 1 > 2 then\n    x := 1 +\nend\nwrite 7\n' > never.mote
$ ./mote0 never.mote
7
```

`late.mote` printed 1 before its second line was even read. And `never.mote`
runs, mistake and all: line 2 is only read past, by its first word, and
nothing else on it is ever looked at.

## How it works

### A name is a search, every time

Every use of a name, and every assignment, runs this loop:

```
  for (Name *n = names; n; n = n->next)
    if (n->len == len && !strncmp(n->s, s, len))
      return n;
```

That is the cost section 1.4 names: where a variable is, looked up in a
table on every use, where a compiler would have decided it once, before the
run. With gcd's two names it is cheap. With many names every use costs a
little more, and a use inside a loop pays it on every pass.

### Blocks found by counting

When a `while`'s condition is false, `mote0` must find the `end` that closes
the loop, and it recorded nothing on the way in. So `skip` reads forward,
line by line, looking at first words. Between the `while` and its `end` there
may be other blocks with `end`s of their own, as gcd's `if` is. The
**invariant** of the search: `depth` is the number of blocks opened since it
started and not yet closed, so the `end` it wants is the one met when
`depth` is 0.

```
    if (is(w, len, "while") || is(w, len, "if"))
      depth++;
    if ((is(w, len, "end") || (to_else && is(w, len, "else"))) && depth == 0)
      return at;
    if (is(w, len, "end"))
      depth--;
```

The same search, with `to_else`, finds an `if`'s own `else`. Going back is
easier: `open[]` keeps each open `while`'s line, and its `end` jumps there.

### The line is the unit

There is no step before the run that cuts the text into words, so the only
place `mote0` can be sure a statement ends is the end of its line. Two
statements on one line are a mistake:

<!-- verify: session -->
```
$ printf 'read i read j\nwrite i + j\n' > one.mote
$ echo 3 4 | ./mote0 one.mote
one.mote:1: expected the end of the line
```

That is why every program in `programs/` keeps to one statement a line, with
`while ... do`, `else` and `end` on lines of their own. Lesson 01.06 builds
the scanner that frees the language from it.

## Decide the boundary

`mote0` runs the text. The other way is to translate it first, once, into
something that runs without reading. Running the text costs the reading and
the searching on every pass of every loop. It buys an interpreter with
nothing to build before the first line runs, and errors that name the line
being run, with the values the program has at that moment. Translating costs
a step before the run, and a mistake reported in terms of what the text was
translated into, unless the translator takes care. The question that
decides it: how many times is each line run? A line run once gains nothing
from being translated; a line in a loop run a million times pays for its
reading a million times. Lesson 01.04 translates.

## Break it

Make the search for a block's `end` stop counting the blocks inside it. In
`build/at/lang/01.03/mote0.c`, in `skip`, delete the two lines

<!-- verify: patch file=mote0.c
-    if (is(w, len, "while") || is(w, len, "if"))
-      depth++;
-->
```
    if (is(w, len, "while") || is(w, len, "if"))
      depth++;
```

and run gcd again:

<!-- verify: session -->
```
$ make -s
$ ./mote0 programs/gcd.mote < programs/gcd.in; echo $?
programs/gcd.mote:10: expected a statement
1
```

The loop runs all 11 passes correctly: the `if` inside it reads forward only
to its own `else`, and nothing is nested between them. Then `i` equals `j`,
the `while`'s condition is false, and the search for its `end` stops at line
9, the `if`'s `end`, because the `if` on line 5 was not counted. `mote0`
carries on at line 10, an `end` with no block open, and stops there; 21 is
never printed. (On `primes.mote` the same mistake sends the run back to the
outer loop's top before `p` changes, and it never ends.) Put the two lines
back.
