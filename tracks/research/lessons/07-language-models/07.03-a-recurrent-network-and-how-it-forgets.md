# 07.03 A recurrent network, and how it forgets

07.02's network reads a fixed number of characters, and each one more
costs a row of weights: in its long run, eight characters did no better
than five. A recurrent network reads one character at a time into a state
it carries along, with the same weights at every step, so in principle it
can use everything it has read. This lesson writes one by hand, trains it
on the text, and then measures how much of the past it really uses, and
why so little: the gradient that would teach it to remember shrinks at
every step back.

## Where this fits

![Where 07.03 fits](figures/07.03-map.svg)

This lesson's piece is the second of the language models: a recurrent
cell, one small layer applied again and again along a sequence, and a
network of the next character built on it. Below it are 07.02's
embeddings and the module's tools for batches and scores, which gain
windows of text read in order. Above it, 07.04's encoder and decoder are
built from this same cell. After this lesson the track has a network that
reads any length of text with one set of weights, and three measurements
of how much of it the network keeps.

## The idea

### One cell, applied again and again

A **recurrent network** keeps a vector of numbers, its **hidden state**
(the state, for short): 256 numbers here, all the network keeps of what it
has read. At each step it reads one character's embedding (07.02) and
makes a new state from it and the old one:

<!-- verify: skip reason="the formula, not code" -->
```
h_new = tanh(ih(x) + hh(h))
```

`ih` and `hh` are two Linear layers, the same two at every step. A
Linear layer from the state gives 65 scores for the next character after
each step. The first state is all zeros; then the network reads the text
a character at a time, and the same cell does the same arithmetic on a
new input and the state it left last time.

![The recurrent network of the page's run (seed 0) reading the first line of the training text a character at a time: the same cell at every step, its state carried to the next](figures/07.03-unroll.svg)

That is the trained network of this lesson reading "First Citizen", the
first line of the training text. After F it guesses a space; after
"First Ci" it gives t 0.76, and after "Citiz" it gives e 0.85. Nothing
in it counts how far back a character was. Whatever it knows of the line
so far is in the state.

### Training it: backpropagation through time

Written out over 64 characters, the network is 64 copies of the same cell,
each feeding the next: a network 64 layers deep whose layers share their
weights. The chain rule of 01.02 runs back through it as through any
other, from each character's loss back along the chain of states. That is
**backpropagation through time**. Each weight's gradient adds up what
every step's copy of it contributed, as a convolution's weight added up
every position's in 06.01.

The text is a million characters long, and a graph of a million steps
will not fit. So the training text is cut into 64 streams laid side by
side, and each step of training reads the next 64 characters of all 64
streams. The state is carried from one piece to the next, so the network
reads each stream continuously, but the gradient is cut at the start of
each piece: it goes back 64 characters at most. That is **truncated**
backpropagation through time.

### Three ways to see it forget

Part 1 of the run trains three seeds and scores them on the test text,
each character with at least 64 before it. Then three measurements:

1. **What it uses.** Each test character is read after 64 characters, of
   which only the last w are the ones really before it in the text; the
   rest are the 64 before some other position. If the score stops changing
   once w passes some length, nothing further back changes the guess.
2. **The recall task.** A smaller network of the same kind reads a
   sequence that starts with one symbol of 8 and goes on with T blanks,
   and must name the first symbol from its last state. Trained for each
   T, three seeds, scored on 1000 new sequences. Chance is 1 in 8.
3. **The gradient that reaches back.** For the recall task with T = 60,
   the size of the gradient of the loss at each input, k steps back from
   the answer: how much the input k steps back can be taught.

### Why the gradient shrinks

One step backwards, by the chain rule:

1. h_new = tanh(a), with a = ih(x) + hh(h). Through tanh, a gradient g
   arriving at h_new is multiplied, number by number, by tanh's slope,
   1 - h_new^2: 1 at h_new = 0, and close to 0 at tanh's flat ends, where
   h_new is near -1 or 1 (04.01 called such a unit saturated).
2. Through `hh`, a Linear layer, it is multiplied by the transpose of its
   weight matrix (02.03).
3. So k steps back, the gradient has been through k such pairs of
   multiplications. A matrix stretches some directions and shrinks others;
   05.04 called the sizes of those stretches its singular values. If each
   step shrinks the gradient by at least some factor q below 1, after k
   steps it is at most q^k as large: it falls geometrically, a straight
   line on a log scale. If the matrix stretches more than the slopes
   shrink, it can grow geometrically instead.

How it works checks steps 1 and 2 against PyTorch's own backward. The
run's part 4 prints, for each network, the matrix's **spectral radius**:
how much it stretches a vector it is applied to again and again, in the
long run. It is never more than the largest singular value.

### The papers

Bengio, Simard and Frasconi's paper of 1994 says the finding in its
title: "Learning long-term dependencies with gradient descent is
difficult". Pascanu, Mikolov and Bengio (2013), "On the difficulty of
training recurrent neural networks", name the two ways it goes: "the
exploding gradients problem refers to the large increase in the norm of
the gradient during training", and "The vanishing gradients problem
refers to the opposite behaviour, when long term components go
exponentially fast to norm 0, making it impossible for the model to learn
correlation between temporally distant events." They prove, for networks of
this form, that the gradient from far back must vanish when the recurrent
matrix's largest singular value is below 1 (for tanh, whose slope is at
most 1), and that it can explode only when that value is above 1: needed,
not enough. And they give the remedy for exploding that this lesson's
training uses, **gradient clipping**: when the gradient's length, the
square root of the sum of the squares of every weight's gradient, is above
a limit, scale the whole gradient down to that length.

### `RNNCell`

One step: the new state from an input and the state before it, tanh of
two Linear layers' outputs added together.

### `RNN`

The cell along a sequence, in a Python loop: the state starts at zeros, or
at a state it is given, each step's new state goes to the next, and every
step's state comes back, with the last.

### `windows`

A batch of windows of the text: for each start, the next `length`
characters, and the character after each of them.

### `window_bits`

A model that scores the next character at every position of a window,
scored over a whole text: the text cut into spans, each read in a window
that starts 64 characters early, so that every character scored has at
least 64 before it.

### `CharRNN`

The network of the next character: embeddings of 32, the recurrent
network with a state of 256, and a Linear layer from the state at every
step to 65 scores.

### `train`

Truncated backpropagation through time: 600 steps of 64 streams by 64
characters, the state carried and cut from the graph, Adam at 0.005 down a
cosine, the gradient clipped to a length of 1, and every gradient's length
kept.

### `recall_task`

A batch of the recall task: a symbol, then blanks, and the symbol as the
answer.

### `Recall`

The network for the recall task: embeddings, a recurrent network with a
state of 64, and a Linear layer from the last state to a score for each
symbol.

### `train_recall`

One recall network for one T: SGD with momentum 0.9 at 0.1 (03.02), as
the papers trained, the gradient clipped as the text network's, 300 new
batches; then its accuracy on 1000 new sequences.

### `gradient_back`

The size of the gradient that reaches each input of a sequence: the
inputs' embeddings made a tensor that needs a gradient, the loss of the
answer, `torch.autograd.grad` of it with respect to them, and its length
at each step, k steps back from the end.

From 20 steps back to 40, every step multiplies it by about 0.49. The
first symbol of a 40-step sequence gets 1e-16 of the push the last blank
gets: nothing it can learn from in 300 steps. With the same weights scaled
to a radius of 0.5 it falls faster still, to exactly 0 by 60 steps, below
the smallest number a float32 holds. Scaled to 1 it still falls, because
every step also multiplies by tanh's slopes, which are below 1. Scaled to
2 and 3 it grows instead, to 2900 at 60 steps back: exploding.

The trained text network is the telling row. Its recurrent matrix has a
spectral radius of 2.95, as large as the row that exploded, and its
gradient still vanishes, from 3.39e-03 at the last character to 1.02e-14
sixty back. The matrix is not what shrinks it: tanh's slopes are. In the
stepped figure above, after its first character, between 139 and 189 of
the network's 256 numbers are beyond 0.9 in size, where tanh's slope
1 - h^2 is below 0.19. Every step back multiplies the gradient by those
small slopes. A radius above 1 is what Pascanu et al. call needed for
explosion, not enough.

## How it works

### The cell, against PyTorch's

`torch.nn.RNN` computes the same recurrence. Its weights are named
`weight_ih_l0`, `bias_ih_l0`, `weight_hh_l0` and `bias_hh_l0`, where these
are the two Linear layers' weights and biases. Copy ours into it, in
float64, and compare; then compare one step's backward with the
derivation's two multiplications. In the project's folder:

<!-- verify: session needs="torch" -->
```
$ cd build/at/research/07.03
$ python3 -c "
import torch
from models.rnn import RNN, RNNCell
torch.manual_seed(0)
ours, theirs = RNN(3, 5).double(), torch.nn.RNN(3, 5, batch_first=True).double()
with torch.no_grad():
    theirs.weight_ih_l0.copy_(ours.cell.ih.weight)
    theirs.bias_ih_l0.copy_(ours.cell.ih.bias)
    theirs.weight_hh_l0.copy_(ours.cell.hh.weight)
    theirs.bias_hh_l0.copy_(ours.cell.hh.bias)
x = torch.randn(2, 7, 3, dtype=torch.float64)
print('the same states:', torch.allclose(ours(x)[0], theirs(x)[0], rtol=0, atol=1e-12))
cell = ours.cell
h = torch.randn(1, 5, dtype=torch.float64, requires_grad=True)
new = cell(torch.randn(1, 3, dtype=torch.float64), h)
g = torch.randn(1, 5, dtype=torch.float64)
(auto,) = torch.autograd.grad(new, h, g)
by_hand = (g * (1 - new ** 2)) @ cell.hh.weight
print('the same gradient:', torch.allclose(auto, by_hand, rtol=0, atol=1e-12))
"
the same states: True
the same gradient: True
$ cd ../../../..
```

Seven steps of two sequences give the same states as PyTorch's to 1e-12,
and the gradient one step back is the slope of tanh times the gradient,
through the matrix `hh`: steps 1 and 2 of the derivation, number for
number. `@ cell.hh.weight` is the multiplication by the transpose: a
Linear layer computes h times the transposed weight, so its backward
multiplies by the weight itself.

### Cutting the gradient between pieces

```
        scores, h = model(x, h)
        h = h.detach()
```

The state that ends one piece starts the next, so the network reads each
stream without a break. `detach()` gives the same numbers with no history:
the next piece's backward stops there instead of running back through
every piece before it, which would need the whole graph of the training
so far, and fails once it has been freed. The state carries what the
network has read; the gradient goes back 64 characters at most.

### Clipping, and what it does not do

```
        norms.append(torch.nn.utils.clip_grad_norm_(model.parameters(), cfg.clip or float("inf")).item())
```

`clip_grad_norm_` measures the length of the whole gradient, every weight
together, scales it down to 1 when it is longer, and returns the length
it measured. For the text network it seldom acts: 5 or 6 of 600 steps.
For the recall network it matters a great deal, as Break it shows. It
works on gradients that are too large. A gradient that has vanished is
too small, and clipping leaves it as it is.

## Decide the boundary

This cell is the plain one: tanh of a sum, nothing else. The cells used in
practice before attention, the LSTM (Hochreiter and Schmidhuber, 1997) and
the gated unit of Cho et al. that 07.04's paper uses, add gates: learned
numbers between 0 and 1 that decide, at each step, how much of the old
state to keep and how much of the new to let in, so that a kept number
passes from step to step multiplied by about 1, and so does its gradient.
They cost three or four times the weights of a plain cell and remember
far longer. The next lesson goes another way: it lets the network look
back at every step directly, with no chain of steps between. Is it better
to make a long chain carry its gradient, or to need no chain?
