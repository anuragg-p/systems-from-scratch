# 01.03 A neuron, a layer, a network

A neuron is the arithmetic of 01.02's figure with its weights kept inside
it: a weighted sum of its inputs, plus a bias, through a relu. A layer is
several neurons reading the same inputs, and a network is layers one after
another. Written on Values, one `backward()` gives the gradient of the
network's output with respect to every weight in it, and this lesson
holds every one of them to the nudge.

## Where this fits

![Where 01.03 fits](figures/01.03-map.svg)

This lesson is still the values piece of the engine; the strip under the
map tells it apart from 01.02. Nothing new goes underneath: a network here

## The idea

![The experiment's network, two inputs, two hidden layers of 4 units and one output, as seed 0 makes it, at the point (0.5, -1.5): 12 + 20 + 5 = 37 weights, counting each unit's bias. Two units are off there, giving 0; the 12 weights in grey, into those units or reading their 0, get no gradient](figures/01.03-network.svg)

<!-- verify: fact cmd='python3 -B -c "from engine.value import MLP; print(len(MLP(2, [16, 16, 1]).parameters()))"' expect=337 -->

01.02's neuron was five Values named one by one and passed in as
arguments. A model that can learn something has many neurons, each with
weights of its own: a small network of two layers of 16 already has 337.
Those weights have to be made, given starting values, kept with their
neuron, and listed, so that a training step can find every one of them.

A **neuron**, or unit, has one weight for each of its inputs and a
**bias**. Given its inputs it computes w1 x1 + w2 x2 + ... + b, and passes
that sum through the **relu**, max(0, sum): the sum itself when it is
positive, else 0. Without the relu, layers of weighted sums would add up
to one weighted sum, however many there were; the bend at 0 is what lets
a network draw something other than a straight line. A **layer** is
several neurons that all read the same inputs; its output is the list of
their outputs. A **multilayer perceptron**, MLP, is layers one after
another, each reading the last one's list. The layers between the input
and the output are **hidden**. The last layer has no relu: its one unit
gives a **score**, which may be any number, negative too.

Every weight and bias is a **parameter**: a number training will move. A
layer of n units reading m inputs has n x (m + 1) of them, a weight per
input and a bias for each unit. The network of this lesson's experiment,
MLP(2, [4, 4, 1]), has 4 x (2 + 1) + 4 x (4 + 1) + 1 x (4 + 1) =
12 + 20 + 5 = 37; the one above has 16 x 3 + 16 x 17 + 1 x 17.

### `Neuron`

Its weights start as random numbers between -1 and 1 and its bias at 0,
each a Value of its own. Calling it on a list of inputs builds the
weighted sum as arithmetic on Values, so the graph of 01.02 is built as it
goes. `parameters()` returns its weights and its bias.

### `Layer`

`nout` neurons, each reading the same `nin` inputs. Its `parameters()`
are all of theirs, neuron by neuron.

### `MLP`

One layer for each size in `nouts`, the first reading `nin` inputs and
each one after reading the layer before; the last is linear. Every
neuron draws its starting weights from one `random.Random(seed)`, so the
same seed gives the same network, number for number, and another seed
another one.

### `nudge_weights`

The experiment, `experiments/network.py`, runs the network on one point,
takes the output's gradient with respect to all 37 weights by one
`backward()`, and checks each against a nudge of that weight:
`nudge_weights()` moves one weight's `.data` by h each way, runs the
network again and puts the weight back. It does this for three seeds,
three different networks.

## How it works

### Weights with no gradient

A relu that is off, whose sum is 0 or less, gives 0 and has a local
derivative of 0: nothing moves its output, so nothing reaches the weights
behind it. The figure shows seed 0. The top unit of layer 1 is off at this
point, so its two weights and its bias get nothing; so does the second
unit of layer 2, its four weights and bias. And each weight that reads the 0 an
off unit gives gets nothing too, since its gradient is that input, 0,
times the gradient above: the three in layer 2 that read layer 1's off
unit, and the one in the output that reads layer 2's. 3 + 5 + 3 + 1 = 12.
The nudge agrees, to the digit: moving any of those weights a little
leaves the unit off and the output where it was. These weights do not
matter at this point. At another point other units are off; training
(01.04) sums the gradient over many points, so each weight is moved by
the points where its unit is on.

<!-- verify: fact cmd='python3 -B -c "from engine.value import Value; from engine.nudge import derivative; a = Value(0.0); a.relu().backward(); print(a.grad, derivative(lambda t: Value(t).relu().data, 0.0))"' expect="0.0 0.5" -->

There is one place where backward and the nudge must disagree: a sum
that is exactly 0. There the relu has no derivative, since its slope is 0
on the left and 1 on the right. The engine takes the left side, 0; the
central nudge averages the two sides: at 0, a.grad and the nudge are
`0.0 0.5`. A sum of computed floats
is almost never exactly 0, so the check is not thrown off in practice.

### Why the last layer is linear

The output is a score that the next lesson reads as one group when it is
above 0 and the other below, so it must be able to go below 0, as seeds 0
and 1 do. Through a relu, seed 1's -1.06663 would be 0, and that relu,
being off, would pass no gradient to any weight in the network: the
network could not even learn its way out.

### Why the weights start at random

Module 00's fit started every weight at 0. A network cannot: units of a
layer that start with the same weights compute the same number, get the
same gradient, take the same step, and stay copies of one another for
ever.

<!-- verify: fact cmd='python3 -B -c "from engine.value import MLP; m = MLP(2, [3, 1]); ps = m.parameters(); [setattr(p, \"data\", 0.5) for p in ps]; m([1.0, 2.0]).backward(); print(*[[p.grad for p in n.parameters()] for n in m.layers[0].neurons])"' expect="[0.5, 1.0, 0.5] [0.5, 1.0, 0.5] [0.5, 1.0, 0.5]" -->

Give every weight of MLP(2, [3, 1]) the value 0.5 and the gradients of its
three hidden units, at the point (1, 2), are `[0.5, 1.0, 0.5] [0.5, 1.0, 0.5] [0.5, 1.0, 0.5]`:
three units that will only ever be one. Random starting weights make the
units differ, so that each can learn something of its own. Rumelhart,
Hinton and Williams say it in one line: "To break symmetry we start with
small random weights." Their network started between -0.3 and 0.3; this
one between -1 and 1. Break it shows the start at 0.

## Break it

Start every weight at 0, as module 00 did. In `Neuron` in
`engine/value.py`, change the weights' starting value:

<!-- verify: patch file=engine/value.py
-        self.w = [Value(rng.uniform(-1, 1)) for _ in range(nin)]
@block
-->
```
        self.w = [Value(0.0) for _ in range(nin)]
```

and run network again (`./learn run research --at 01.03 -- network`):

<!-- verify: session run="./learn run research --at 01.03 -- network" timeout=120 -->
```
seed 0: 37 weights, output +0.00000, 36 with no gradient (behind a relu at 0), largest difference from the nudge 0.0e+00
seed 1: 37 weights, output +0.00000, 36 with no gradient (behind a relu at 0), largest difference from the nudge 0.0e+00
seed 2: 37 weights, output +0.00000, 36 with no gradient (behind a relu at 0), largest difference from the nudge 0.0e+00
```

The three seeds now print the same line: the seed no longer reaches any
weight. Every hidden unit sums to its bias, 0, so every relu is off, and
every weight behind one gets nothing; the output's four weights read
those zeros and get nothing either. Of 37, only the output's bias gets a
gradient, so a training step could move only that one number, and the
network would stay a constant for ever. It is the copies of How it works
at their worst: every unit of every layer the same, and that same unit
off. The backward pass is not wrong here (the nudge agrees exactly); the
network is. Put `rng.uniform(-1, 1)` back.
