# 09.03 Loading GPT-2: the same logits as the reference

Module 08 built a GPT and shaped it so that this lesson could happen:
OpenAI's published weights for GPT-2 small, 124 million of them, loaded
into it. The file names every tensor its own way, keeps three layers'
weights in one, and stores every weight matrix the other way round from
PyTorch's Linear layer; one of them is square, so loading it the wrong
way round raises no error and ruins the model. Loaded right, the model
gives the same logits, the scores before the softmax, as the reference,
the implementation most code uses, to the last bit. Then the real model is measured as
08.05 measured our small ones, with Holtzman et al.'s (2020) numbers:
greedy loops and a lower temperature brings loops back, as they found;
the nucleus is not the closest to the real text, as they found it was.

## The idea

### The checkpoint and the GPT

GPT-2 small is a GPT of 12 blocks of 12 heads, width 768, windows of
1,024 tokens and a vocabulary of 50,257, Radford et al.'s (2019) smallest
model. Module 08's GPT was written to be that model at other sizes: the
same blocks in the same order, layer norm before attention and before the
MLP and once more at the end, learned positions, GPT-2's GELU, and the
output layer tied to the token embedding. With GPT-2's sizes,
`GPT(**CONFIG)` has 124,439,808 weights, the count of the published
file. What differs is only how the file keeps them.

![GPT-2's checkpoint beside the GPT of module 08, for block i of 12: the file's names and shapes, ours, and the weights that must be transposed, in the accent](figures/09.03-names.svg)

- **Names.** The file says `wte.weight`, `h.0.attn.c_attn.weight`; the
  GPT says `tokens.weight`, `blocks.0.attention.query.weight`. A table
  of names, read from the file's own header.
- **One tensor for three layers.** `c_attn` holds the queries', the
  keys' and the values' weights side by side, 768 columns each, in that
  order.
- **Transposed.** GPT-2's layers compute `x @ W + b` with `W` kept as
  (inputs, outputs). PyTorch's `nn.Linear` keeps (outputs, inputs) and
  computes `x @ W.T + b`. So every weight matrix of the four kinds of
  layer, `c_attn`, `attn.c_proj`, `mlp.c_fc` and `mlp.c_proj`, goes in
  transposed. The embeddings and the layer norms go in as they are.
- **A bias that is not one.** `h.0.attn.bias` is the causal mask, a table
  of ones and zeros of 1,024 by 1,024 for each block, 48 MB of the file.
  The GPT makes its own mask: it is left out.

PyTorch's `load_state_dict` refuses a name that is missing, a name too
many, or a shape that does not fit. That catches every mistake but one.
`attn.c_proj`, the output of attention, is 768 by 768: loaded
untransposed, its shape fits, and nothing complains.

### Reading 548 MB

02.05's `load_file` read the whole file into memory, copied its data
part, and copied each tensor out of that: for GPT-2's 548 MB it held over
two gigabytes at its peak, four times the file. From this lesson it reads
the header, checks every tensor's range before reading anything, then
reads each tensor from the file straight into an array of its own.

![Reading GPT-2's 548 MB file in a fresh python: the most memory the process held at once, with 02.05's load_file and with 09.03's](figures/09.03-memory.svg)

The same arrays come out, tensor for tensor and value for value, as the
safetensors library gives, and 02.05's checkpoints load as before.

### The reference

The model is right if it gives the same numbers as code everyone else
uses: transformers' `GPT2LMHeadModel` (version 4.57.6 here), loaded from
the same fetched file with no network, with its plain attention. It is
not part of the project. On 1,024 tokens of Tiny Shakespeare and on 4
rows of 64 random tokens, the largest difference between its logits and
this GPT's, logits up to 342 in size, was 0.0, in float32 and in float64.
Not close: equal. The two do the same operations in the same order: the
same products, the same GELU formula, the same softmax of the same
masked scores. With transformers' default attention, a fused kernel that
adds in another order, the largest difference was 0.0041.

With `attn.c_proj` loaded untransposed instead, the logits were off by
111 to 323, and the likeliest next token agreed with the reference's at
7.6% of positions. The run's part 2 shows what that does to a score.

### 08.05's measurements, on the real model

08.05 ran Holtzman, Buys, Du, Forbes and Choi's (2020) measurements on
characters, where most of them did not hold. They had measured GPT-2
Large on word pieces, and now the project has GPT-2 too: their own kind
of model, with their tokenizer, if a smaller size. The run gives it the
starts of speeches of the test text and lets it write after each, every
way of choosing 08.05 wrote, and scores what it wrote by the model's own
perplexity, 2 to its bits per token, beside its perplexity of what the
text really says next; and how many passages end in a loop, a phrase of
two or more tokens three times over.

### What the run does

1. Loads GPT-2 small and shows what it expects after "The meaning of
   life is", and a greedy continuation.
2. Loads it again with `attn.c_proj` untransposed in every block, and
   scores both on the first 1,986 tokens of the test text.
3. GPT-2's bits per character on Tiny Shakespeare's test text, each token
   read with 64 or more before it, beside modules 07 and 08's models.
4. 8 prompts of 16 tokens, 40 tokens written after each, 2 seeds of the
   sampling: perplexity and loops for each way of choosing.

### `from_gpt2`

The file's tensors under the GPT's names, in the GPT's shapes: renamed,
`c_attn` cut in three, every Linear weight transposed, the mask left out.
Transposed views, no copies.

### `load`

GPT-2 small in the GPT: `GPT(**CONFIG)`, the file read by
`lab/safetensors.py`, the tensors put in by `from_gpt2()` and
`load_state_dict`, in eval mode.

### `perplexity`

The model's perplexity of continuations after their prompts, each token
read with its prompt and everything before it.

### `loops`

Holtzman et al.'s repetition, 08.05's measure, for any symbols: whether
a list ends in a phrase of 2 or more symbols repeated 3 times in a row.

## How it works

### The table of names, as code

```
        w, bias = tensors[h + "attn.c_attn.weight"], tensors[h + "attn.c_attn.bias"]
        for j, name in enumerate(("query", "key", "value")):
            out[f"{b}attention.{name}.weight"] = w[:, j * width:(j + 1) * width].T
```

`w` is (768, 2304): inputs down, the three layers' outputs across. Its
first 768 columns are the queries' weights, then the keys', then the
values', the order OpenAI's code splits them in. A slice of columns,
transposed, is a (768, 768) view of the file's array in nn.Linear's
order; nothing is copied until `load_state_dict` copies it into the
model.

### Every Linear weight, the square one too

```
        for ours, theirs in (("attention.out", "attn.c_proj"), ("mlp.up", "mlp.c_fc"), ("mlp.down", "mlp.c_proj")):
            out[b + ours + ".weight"], out[b + ours + ".bias"] = tensors[h + theirs + ".weight"].T, tensors[h + theirs + ".bias"]
```

`mlp.c_fc` is (768, 3072) in the file and (3072, 768) in the GPT: without
the `.T`, `load_state_dict` stops with a size mismatch. `attn.c_proj` is
(768, 768) both ways, and its `.T` is the one line nothing else checks.
Comparing logits with the reference does.

### Each tensor straight from the file

```
            out[name] = np.fromfile(f, dtype=dtype, count=count).reshape(spec["shape"]).astype(
                dtype.newbyteorder("="), copy=False)
```

The file is already open at the start of the data, and the tensors are
read in the order of their byte ranges, which were checked to follow on
from each other with no gap; so each `np.fromfile` reads exactly one
tensor's bytes, into an array that owns them. On a little-endian machine
`astype(..., copy=False)` is no copy at all. The peak is about the arrays
themselves.

### What the model wrote, scored in one window

```
    rows = torch.cat([prompts, continuations], dim=1)
    with torch.no_grad():
        scores = model(rows[:, :-1])[:, prompts.shape[1] - 1:]
```

A prompt and what followed it go through the model as one row, as GPT-2
read them when it wrote. The scores from the prompt's last position on
are the guesses for each continuation token, each with its prompt and
everything before it in view. 08.05 scored characters the same way; here
the symbols are word pieces and perplexity is per token.

## Decide the boundary

GPT-2 scores 1.851 bits per character on a text the track's models never
trained on, and nobody here knows whether GPT-2 did. WebText is links
people shared from one site; a play by Shakespeare is on many pages of the
web. A model that saw the test text scores well for the wrong reason, and
the larger the training set, the harder that is to rule out: the track
can split its own data by position, but not OpenAI's. When a model's
training data is not yours, what would you need to check before calling
its score on a test text a result?

Every shape fits, so it loads, and every name is right. The model is
ruined: 3.943 bits per character, worse than the pair model, and the
real text's perplexity is 3,591 where it was 64.74. Its likeliest next
tokens are the commonest words of English, whatever came before. The
score of position i for position j was the query of i times the key of
j; with the two swapped it is the key of i times the query of j, which
is the real model's score of j for i. Every block reads its table of
scores turned over, the upper triangle the mask throws away in place of
the lower one it keeps. A file's layout is a fact to read from its
source, not a convention to assume. Put the order back.
