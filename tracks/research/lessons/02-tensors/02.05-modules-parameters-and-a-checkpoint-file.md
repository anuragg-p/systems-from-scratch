# 02.05 Modules, parameters, and a checkpoint file

Until now a network has been a list of weight tensors that each script
makes, updates and throws away by hand. This lesson gives the engine
PyTorch's way of holding a network: modules that own their weights and
name them, the layers built from them, and a file that keeps a trained
network's weights after the run ends, in the safetensors format that
PyTorch's own tools read.

## Where this fits

![Where 02.05 fits](figures/02.05-map.svg)

This lesson's piece is the layers box of the engine row, and it brings the
checkpoints box of the lab with it. A layer is a module: a piece of a
network that holds its own weights. It is built on the tensors and the loss
of the lessons before it. Above it, every network from here on is a stack
of such layers, and module 03's optimisers will take their weights from
it. The checkpoint is the lab's way of keeping what a run learned.
After this lesson a network written the way PyTorch writes it runs on this
engine, and its trained weights outlive the process, readable by this
engine or by PyTorch.

## The idea

![nn.Sequential of five modules, and the names its weights get in state_dict: the module's name, a dot, the attribute's name](figures/02.05-names.svg)

In 02.03 the two groups were trained with a network that was a Python list
of `(w, b)` pairs, made by the script's own `init`, run by its own
`forward`, updated by its own `sgd_step`, and lost when the script ended. A
PyTorch script writes the same network as `nn.Linear(2, 16)` and friends.
02.04's engine, in `build/at/research/02.04/`, has none of them:

Two ideas fix that. A **parameter** is a tensor that is a weight: it needs a
gradient, and anything that trains or saves the network must find it. A
**module** is a piece of a network that owns parameters, and other modules,
as its attributes. When a module sets `self.weight = Parameter(...)`, it
files the weight under the name `weight`; when it sets an attribute to
another module, it files that too. So the whole network is a tree, and a
walk down it finds every weight and names it by its path: the figure's
`0.weight` is the attribute `weight` of the module called `0`. Those names
and tensors, as a dictionary, are the network's **state dict**, and the
names are the ones PyTorch gives the same network.

A **checkpoint** is a state dict written to a file. This engine writes it
in the **safetensors** format, which is three parts and nothing else:

1. 8 bytes: the length N of the header, as an unsigned 64-bit integer,
   least significant byte first (**little-endian**).
2. N bytes of JSON: for each tensor its name, its type (`F32` for float32),
   its shape and the range of bytes its numbers take in the third part,
   `data_offsets`; and, if given, `__metadata__`, a few strings.
3. Every tensor's numbers, back to back, 4 bytes each for float32,
   little-endian, row after row.

A program that reads it reads numbers and names, never code. The figure in
How it works shows the file the experiment writes, byte for byte.

### `Parameter`

A `Tensor` that requires a gradient by default, and whose type is how a
module tells a weight from any other attribute. It shares the numbers it is
made from.

### `Module`

The base of every layer. `__setattr__` files parameters, modules and
buffers (tensors to save that are not weights) in three ordered
dictionaries as they are set. `named_parameters` walks them, its own first
and then each child's under the child's name, giving each weight once;
`parameters` is the same without the names. `state_dict` gives the
parameters and buffers by name, sharing their numbers; `load_state_dict`
copies a dictionary's numbers back in. `zero_grad` forgets every gradient,
`train` and `eval` set a flag on every module below, and calling a module
runs its `forward`.

### `Linear`

y = x @ weight.T + bias, with `weight` of shape `(out_features,
in_features)`, the way PyTorch keeps it, which is why the product needs the
`.T`. Both start uniform between -1/sqrt(in) and 1/sqrt(in), as PyTorch's
do, drawn from the engine's generator.

### `ReLU`

`ReLU` and `Tanh`: the activations as modules, with no weights, so they
can sit in a `Sequential` between the layers.

### `Sequential`

Modules applied one after another, filed under the names `"0"`, `"1"`,
... which is where the names in the figure come from.

### `manual_seed`

The engine's random numbers come from one numpy generator, and
`torch.manual_seed(seed)` starts it again: the same seed gives the same
starting weights on every run. They are not PyTorch's numbers for the same
seed, since its generator is not numpy's.

### `randn`

A tensor of random numbers from the normal distribution, mean 0 and
variance 1, from the engine's generator.

### `rand`

A tensor of random numbers uniform between 0 and 1, from the same
generator.

### `save_file`

Writes a dictionary of numpy arrays in the format above, names in sorted
order, as the safetensors library's `save_file` does for numpy. It takes
numpy arrays, not tensors, so a state dict from this engine or from PyTorch
goes in the same way, as `{name: tensor.numpy()}`.

### `load_file`

Reads one back into a dictionary of numpy arrays, and checks what a reader
must before trusting it: the header fits in the file, every type is known,
each tensor's bytes are exactly the size its shape says, and the tensors
cover the data part from end to end with no gaps and no overlaps.

### `train`

The two groups again, now with a network of `nn` layers and
`F.cross_entropy` with two classes: full-batch descent written by hand,
since optimisers are module 03's. Each step is the loss, `zero_grad`,
`backward`, then every parameter moved inside `no_grad()`.

`\xa8\x01` and six zeros is 0xa8 + 0x01 * 256 = 168 + 256 = 424, least

## How it works

![The checkpoint the experiment writes, to scale: the 8-byte length, the 424-byte header, then every tensor's numbers back to back](figures/02.05-file.svg)

### Registration by assignment

```
def __setattr__(self, name, value):
    if isinstance(value, Parameter):
        self._parameters[name] = value
    elif isinstance(value, Module):
        self._modules[name] = value
```

This is the whole trick. A layer never lists its weights for anyone; it
sets them as attributes, as any Python object would, and `__setattr__`
files each one by its type, in the order set. The **invariant** is that
every parameter reachable from a module is in some `_parameters` on the way
down, so `parameters()` finds exactly the weights to train and
`state_dict()` exactly the ones to save. PyTorch's `Module.__setattr__`
does the same. Break it shows what happens without it.

### Loading copies into the weights already there

```
t.data[...] = src
```

`load_state_dict` does not swap in new tensors: it copies the file's
numbers into the arrays the network already has. Anything already holding
those parameters, such as module 03's optimisers, keeps working with the
loaded weights. Before copying, it refuses a name the network lacks, a name
the file lacks, or a different shape, so a checkpoint of another network
fails loudly instead of loading half.

### The header ends where 8 divides

```
text += b" " * (-(8 + len(text)) % 8)
```

`save_file` pads the JSON with spaces so that 8 plus its length is a
multiple of 8: here 423 bytes of JSON and one space make 424, and the
numbers start at byte 432, on an 8-byte boundary of the file. The
safetensors library's own writer pads the same way. `load_file` does not
depend on it, but a file this engine writes looks, byte for byte, like one
the library would.

## Decide the boundary

This engine saves numbers and names and nothing else: to load a checkpoint,
the script must build the network first, with its own code, and then fill
it. PyTorch's `torch.save` uses Python's pickle, which can save any Python
object, a whole model with its class, in one call. Loading a pickle runs
whatever code it was made to run, so a checkpoint from someone else is a
program from someone else. safetensors cannot hold code, and pays for it by
needing the code from somewhere else. Should your checkpoint be able to
rebuild anything, or be safe to open whoever made it?

## Go deeper

- [safetensors README, "Format"](https://github.com/safetensors/safetensors#format) - the
  format this lesson writes: the 8-byte little-endian length, the JSON header with `dtype`,
  `shape` and `data_offsets` and the string-only `__metadata__`, padding with spaces; and,
  further up, why it exists: pickle "runs arbitrary code", and a byte buffer with no holes
  rules out polyglot files.

  - "What is a state_dict?", and how `torch.save` and `torch.load` use pickle.
- [PyTorch: torch.nn.Linear](https://docs.pytorch.org/docs/stable/generated/torch.nn.Linear.html)
  - y = xA^T + b, the weight of shape (out_features, in_features), and the uniform start with
  k = 1/in_features, which this engine's `Linear` copies.
- [PyTorch's module.py](https://github.com/pytorch/pytorch/blob/main/torch/nn/modules/module.py)
  - the real `Module`: its `__setattr__` registers parameters and modules as this one does,
  with `state_dict` and `load_state_dict` beside it, and much more.

  Network Library Abstractions": why libraries settle on modules, parameters and optimisers
