# 11.03 Attention without the big matrix

08.01's attention is written out: for every head of every window a
table of scores, one for each pair of positions, the mask, a softmax
into a second table of weights, and the weighted sum of the values; the
backward pass keeps the weights. 11.02 found that this is the largest
piece of a training step. Dao et al. (2022), FlashAttention, compute the
same sums in one kernel that never writes the table out and keeps, for
the backward pass, only a total for each row. This lesson puts PyTorch's
fused attention, which works that way, in place of the written-out one,
behind one argument of the GPT. It gives the same numbers, to 2.7e-15 in
float64. On this laptop's CPU, attention alone is 1.6 to 4.5 times
faster, a whole training step 1.29 to 1.42 times, and the memory kept
for the backward pass grows with the window's length instead of its
square. On the Apple GPU it gives nothing.

## Where this fits

![Where 11.03 fits](figures/11.03-map.svg)

This lesson's piece is fast, in the models row: the GPT's attention
computed by one fused kernel instead of written out, chosen by an
argument whose default leaves every earlier lesson as it was. It
replaces 08.01's `self_attend` inside a block, after module 10's rotary
turning and grouped heads have made the queries, keys and values, and
before the Linear layer out. It is checked against 08.01's attention in
float64, timed as 11.01 times, and its memory counted from what
autograd keeps. After this lesson the GPT trains a little sooner on this
CPU and can read long windows without a table of every pair of
positions.

## The idea

### What written-out attention keeps

For a window of T positions, each head makes a T by T table of scores,
q_i . k_j for every pair, and then a second table of weights, the
softmax of each row. Each table is a pass over memory to write and
another to read. For the backward pass autograd keeps what each
operation needs to make its gradient: the product with the values keeps
the weights, so for every head of every window a T by T table stays in
memory until the backward pass has used it. At 256 places, for 8
windows of 4 heads, that is 8 MiB of weights where the queries, keys
and values are 1.5 MiB together; at 1024 places, 128 MiB. The table
grows with the square of the length.

![What autograd keeps for the backward pass of one attention at 256 places, 8 windows x 4 heads of 16, every tensor it saves, to scale: written out, the (T, T) weights; fused, a total for each row](figures/11.03-kept.svg)

### Dao et al.: never write the table out

Dao, Fu, Ermon, Rudra and Re, "FlashAttention: Fast and Memory-Efficient
Exact Attention with IO-Awareness" (2022): "an IO-aware exact attention
algorithm that uses tiling to reduce the number of memory reads/writes
between GPU high bandwidth memory (HBM) and GPU on-chip SRAM". A GPU's
large memory is far from its arithmetic; a small, fast memory sits
beside it. "Our main goal is to avoid reading and writing the attention
matrix to and from HBM." Two things do it. The keys and values are taken
in blocks small enough for the fast memory, and the softmax of each row
is built up block by block, keeping the running largest score and the
running total of its row. And for the backward pass only that total is
kept: "We store the softmax normalization factor from the forward pass
to quickly recompute attention on-chip in the backward pass." The
weights are worked out again when they are needed. That is more
arithmetic and less memory; the paper's figure 2, on one attention of
GPT-2 medium on an A100, has the standard way at 66.6 GFLOPs, 40.3 GB
read and written and 41.7 ms, and theirs at 75.2 GFLOPs, 4.4 GB and 7.3
ms. Memory kept is "linear in sequence length".

Their claims, from the abstract: "15% end-to-end wall-clock speedup on
BERT-large (seq. length 512) compared to the MLPerf 1.1 training speed
record, 3x speedup on GPT-2 (seq. length 1K), and 2.4x speedup on
long-range arena (seq. length 1K-4K)"; and in section 4.3, attention
alone "up to 3x faster than the PyTorch implementation" and "up to 20x
more memory efficient". Every number is on NVIDIA GPUs: "We focus here
on GPUs." A CPU appears only in their figure 1, as the slowest memory.

### PyTorch's fused attention

`F.scaled_dot_product_attention(q, k, v, is_causal=True)` computes the
same thing as `self_attend`: the scores, divided by sqrt(d) unless told
otherwise, the causal mask, the softmax and the weighted sum, in one
call. PyTorch 2.10's documentation says it has three implementations,
FlashAttention-2, a memory-efficient one and "a PyTorch implementation
defined in C++ matching the above formulation", and that "The function
may call optimized kernels for improved performance when using the CUDA
backend. For all other backends, the PyTorch implementation will be
used." On this CPU the profiler names the kernel that runs:
`aten::_scaled_dot_product_flash_attention_for_cpu`, a flash kernel of
PyTorch's own for the CPU, and it keeps what a flash kernel keeps.
What the documentation says about other devices is not what runs here;
the profiler is the one to believe.

`GPT(fused=True)` passes the setting to every block, and each block's
attention calls the fused function where it called `self_attend`. It
returns the sums and no weights; 08.02's `attention_maps`, which draws
the weights, keeps the written-out function.

### Memory, counted exactly

How much memory a process uses moves with everything else in it and
with the allocator. What attention changes is what autograd keeps for
the backward pass, and that can be counted exactly: PyTorch can be asked
to call a function on every tensor an operation saves for its backward
pass (`saved_tensors_hooks`). Counting each piece of memory once,
however many operations save it, gives the bytes kept: the same on
every run and every machine.

### What the run does

1. The same numbers, in float64: `fused_attend` against `self_attend`
   with the mask and the division on and off; the baseline GPT written
   out and fused, the same weights, its scores and every gradient.
2. Attention alone, forward and backward, at lengths 64 to 1024 for 8
   windows of 4 heads: the time, the smallest of 5, and the memory kept,
   written out and fused, beside the size of the weights alone.
3. A whole training step of 11.01's baseline at windows of 64 and 256.
4. The baseline trained written out and fused from the same seeds and
   batches, 150 steps, 2 seeds: the bits on the test text and the time
   a step.

### `fused_attend`

`self_attend`'s sums from PyTorch's one fused kernel: the mask as
`is_causal`, the division by sqrt(d) as its default scale.

### `kept_bytes`

The bytes autograd keeps for the backward pass while a piece of work
runs, each piece of memory counted once.

## How it works

### One argument, the same block

```
        if self.fused:
            y = fused_attend(q, k, v, self.mask, self.scale)
        else:
            y, _ = self_attend(q, k, v, self.mask, self.scale)
```

`SelfAttention.forward()` makes the queries, keys and values as before,
turned by rotary positions and repeated for grouped heads (module 10),
and only the last step changes. `fused` defaults to `False` in
`SelfAttention`, `Block` and `GPT`, so every model built before this
lesson is built as it was, and a checkpoint of modules 08 to 10, whose
settings do not name it, loads as before. A loaded model can be switched
by setting `fused` on each block's attention.

### The mask and the scale, translated

```
    return F.scaled_dot_product_attention(q, k, v, is_causal=mask, scale=None if scale else 1.0)
```

`self_attend`'s `mask=True` is `is_causal=True`, the triangle that lets
a position look at itself and every position before it; its
`scale=True`, the division by sqrt(d), is PyTorch's default scale,
`None`, and turning the division off is a scale of 1.0. The run checks
all four combinations against `self_attend`. One thing does not
translate: `is_causal` puts its triangle at the top left, which is
right only when there are as many queries as keys; 11.06 meets the case
where there are not.

### Each piece of memory once

```
        seen[t.untyped_storage().data_ptr()] = t.untyped_storage().nbytes()
```

The softmax saves the weights for its own gradient, and the product
with the values saves them again; both are the same memory. Keying by
where the memory starts counts it once, which is what the machine
holds. (Counting a tensor once for each operation that saved it put the
written-out way at 263 MiB at 1024 places, the weights twice.)

## Decide the boundary

PyTorch's fused function chooses its own kernel for the device, the
types and the shapes it is given, and the same line of code ran a flash
kernel on this CPU and the formula as written on the Apple GPU. The
alternative is a kernel of one's own, as the paper wrote one in CUDA,
which runs exactly where its author put it and must be written again
for each new kind of attention, as the paper's own limitations say. The
price of the first is that what runs is found out, by a profiler, not
read in the code. Which would you rather have under a result that
depends on attention's memory: the call that picks, or the kernel you
know?

an eighth of the written-out one's and far below anything the

see the positions after it, the character it is asked to guess among
them, so it learns to copy the answer. Training and scoring use the same
model, so nothing in part 4 alone says anything is wrong. Part 1 does:
the sums are 3.78 apart, not 2.7e-15. A speed-up comes with the check
that the numbers are the same, run first, because a change that breaks
the model can look like the best result of the module. Put `mask` back.
