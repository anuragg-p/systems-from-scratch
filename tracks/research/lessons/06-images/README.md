# Module 06 - Images: convolution and residual networks

Module 05 judged networks by digits they had not seen; this module moves to images as images, and then to photographs. It starts by giving the engine its last layers: a convolution, which lays the same few weights on every window of an image, and max pooling. LeCun et al.'s claims for them are run again on digits that have moved: the convolutional network, with a ninth of the weights, is better and loses less, and it is still far from indifferent to where a digit is, because its convolutions move their features with the digit exactly and its last layer reads each place with weights of its own. Then the same scripts move to PyTorch by changing one line. The two libraries take the same training step to the last digit a float64 can hold, PyTorch is only about twice as fast on this laptop's CPU, and the switch is made for the GPU and for what the later modules need; from here on every script has a device setting whose default is the CPU, a clock that waits for the device, seeds for the data and for the weights, and networks shared from one folder. On CIFAR-10's photographs, read from the dataset's own bytes, the convolutional network beats the fully connected one with a twenty-third of the weights, and a new crop and mirror image of every picture at every pass closes the gap between training and test accuracy: 3 points of test accuracy here, none on a longer run. The module ends with He et al.'s residual network for CIFAR-10, 20 against 56 layers: in a recorded run of 40 minutes on the CPU the deeper plain network trains worse and the deeper residual one better, both as the paper found, at a laptop's size and far from its errors. It stands on module 04's initialisation, batch norm and residual block and on module 05's augmentation. After it the track works in PyTorch, on photographs, with a residual network that later questions can change.
