# 10.05 Which change paid: an ablation table

10.01 to 10.04 each set one change against the piece it replaced. This
lesson asks the question of all four at once, on one footing: module
08's GPT, each change alone, and all four together, trained on the same
text for the same steps from the same seeds, every row's difference from
the base weighed against the spread of its seeds. The page's run, under a
minute, and the module's recorded long run, 42 minutes, answer it
differently. In the short run rotary positions are far ahead and SwiGLU
is behind, beyond the noise, so all four together are behind rotary
alone. In the long run SwiGLU is the largest single gain and rotary the
next, both beyond the noise; RMSNorm and grouped heads change nothing the
seeds can see; and all four together are the lowest row, with a tenth of
the weights gone.

## Where this fits

paid, at which budget, and how sure it is.

## The idea

### An ablation

An **ablation** measures what each part of a design is worth by changing
that part alone and keeping everything else. Here every change is added
to module 08's GPT on its own, one row each, and all four together make a
sixth row. Every row trains on the same text, the same batches, the same
number of steps, from the same seeds, and the base row is the same runs
for every comparison. A row's number is its mean over the seeds, and its
difference from the base counts only when it is wide next to the spread
of both: Welch's t (00.03), the difference of the means over the spread
of that difference. This page calls a row **beyond the noise** when |t|
is 3 or more; with two or three seeds a row, t is itself rough, and a
row near the line says little either way.

### What a short run can tell

The changes do not pay at the same time. 10.02 found rotary positions far
ahead after 150 steps; 10.03 found SwiGLU behind after 150 steps and
ahead after 600. A table made at one budget answers for that budget. So
the module has two: the page's run, small and short, which a reader can
run in under a minute, and a long run, recorded once, at a size and
length chosen for the question the short run cannot answer: which
changes still pay once the model has trained.

### The long run

Before choosing it, the same six rows were run as trials: at the page's
size for 600 and 1,200 steps, rotary's lead fell from 0.24 to 0.16 bits
and SwiGLU's grew from 0.04 to 0.05; a wider model of 6 blocks of 192
was too slow for 18 runs in the hour. So the hour went to a longer
budget at a modest size: 4 blocks of 4 heads, width 128, windows of 128
characters (818,048 weights for the base), 2000 steps of 32 windows,
about eight passes over the training text, AdamW at 0.002 (08.04's long
run's rate) after 100 steps of warmup, then a cosine; 6 rows of 3 seeds,
42 minutes of this laptop's CPU with other work running. It saved no
weights. Its runs, curves, times and what it printed are in
`experiments/recorded/ablation/`, and the page's run prints its table.

### What the run does

1. The short run: 6 rows, 4 blocks of 4 heads, width 64, windows of 64,
   80 steps of 32, 2 seeds a row; each row's validation bits on 32 fixed
   windows every 20 steps; the table, and the curves.
2. The recorded long run's table, read from its summaries, and each
   paper's claim beside it, with the size it was made at.

### `table`

One row a variant: its weights, its bits over the seeds, its difference
from the first row with Welch's t, whether that is beyond the noise, and
its ms a training step.

not a recipe for their sum, and only the row that has them all says what
the whole is worth.

## How it works

### The line drawn at 3

```
        beyond = ("yes" if abs(t) >= 3 else "no") if r["bits"] is not base else ""
```

Welch's t is the difference of two means over the spread of that
difference; with 3 seeds a side its typical size by chance alone is
about 1, and above 3 by chance is rare. The line is a convention fixed
before the long run was read, not a law: a row at t = 2.6, RMSNorm's in
the long run, is "no" here and would be "yes" at a line of 2.5. What the
table does with a row near the line is say "no" and print the t, so a
reader can see how near.

### The base is the first row

```
    base = next(iter(rows.values()))["bits"]
```

Every row is compared with the base's own runs, not with a number from
another lesson: the base row is trained in the same run, on the same
batches and seeds, taking turns with the others, so whatever the machine
or the data's order did to it, it did to them.

### The same held-out windows for every row

```
    held = windows(val_t, torch.from_numpy(np.random.default_rng(0).integers(0, len(val_t) - cfg.context, cfg.held))
                   .to(dev), cfg.context)
```

The validation curve of every row and every seed is scored on the same
windows, drawn once from a generator of its own, so the curves can be
put side by side and subtracted: the curves figure above is exactly
that, row by row, less the base. They are validation windows, The Taming
of the Shrew; the table is on the test text, as every lesson scores.

### Read back, not run again

```
        rows[name] = {"bits": [s["test_bits"] for s in got], "weights": got[0]["weights"]}
```

Part 2 reads the recorded run's `summary.json` files, one a seed, and
makes its table with the same `table()` as part 1; the times come from
the run's `times.json`, kept apart because a time is never written into
a summary. The long run was this same script with bigger settings and
`recorded=none`, so that it did not try to read itself.

## Decide the boundary

The short run and the long run rank SwiGLU at opposite ends, and both
are honest measurements. Papers report the budget their claim was made
at; a lab deciding what goes into its next model has a budget of its
own, often far larger, and runs its ablations far smaller. 10.03's longer
runs found the turn between 150 and 600 steps at this size; at another
size it may come later, or, as the long run here suggests, sooner. How
long must an ablation run before its ranking is the ranking at the
budget you care about, and how would you know without running that
budget?

did. With 3 seeds a side, a t of 2 or more happens by chance alone
about one time in eight, and this table has five rows: a line of 2 would
call some row a finding in a good share of tables made of changes that
do nothing at all. A line is chosen before the table is read, and kept.
