# 12.04 What fine-tuning forgot: measuring before and after

Each fine-tune of this module moved GPT-2's weights for one task. A
fine-tuned GPT-2 is still a model of the next token, so what it gave up
can be measured the way 09.03 measured GPT-2: its bits on text it was
not tuned on, before and after. Biderman et al. (2024) found that LoRA
"learns less and forgets less" than training every weight; 12.02 found
the first half here. This lesson measures the second, for the
classifiers of 12.02's recorded run and for 12.03's instruction model,
beside how far each fine-tune moved the weights. Whether LoRA forgot
less depends on the text: on held-out TinyStories it did, on
Shakespeare it did not. LoRA moved the weights further than training
every weight did, so the distance moved does not predict what is
forgotten. And instruction tuning of every weight, for 30 steps, made
Shakespeare more likely, not less: measured, and why is not.

## Where this fits

![Where 12.04 fits](figures/12.04-map.svg)

This lesson's piece is the last of module 12, in the models row: the

Shakespeare (07.01) and TinyStories (09.04). After this lesson every
fine-tune of the module has a number for what it cost beside the number
for what it bought, and module 13 asks how sure such numbers are.

## The idea

### What forgetting means here

A fine-tune is judged on its task, and a model tuned on bank questions
will be used on bank questions. But the model's other abilities are not
free to lose: a chat model tuned to answer in a template still has to
write English. **Forgetting** here is how much less likely the tuned
model finds ordinary text that it was not tuned on, measured as 09.03
measured GPT-2: bits per character on Tiny Shakespeare's test text,
each token read with 64 or more before it in windows of 1,024 (GPT-2:
1.851), and bits per byte on the first 50 held-out TinyStories (GPT-2:
0.8257). Higher after tuning is forgetting; lower is the opposite.

### Biderman et al.: LoRA learns less and forgets less

Biderman, Portes, Gonzalez Ortiz, Paul, Greengard, Jennings, King,
Havens, Chiley, Frankle, Blakeney and Cunningham, "LoRA Learns Less and
Forgets Less" (2024), tuned Llama-2-7B on code and on mathematics, with
LoRA and with every weight. From their abstract: LoRA "better maintains
the base model's performance on tasks outside the target domain", and
full fine-tuning "learns perturbations with a rank that is 10-100x
greater than typical LoRA configurations". Their forgetting is a
benchmark score, "the average of HellaSwag, ARC-Challenge and
Winogrande" (their figure 2), and their LoRA adapts every layer of a
block, not 12.02's W_q and W_v. Here the question is theirs at laptop
size: GPT-2 small, a few hundred steps, bits on untuned text.

### How far the weights moved

A second number for each fine-tune: how far it **moved** the weights,
the length of the change of all of them laid end to end, over the length
of the weights before:

<!-- verify: skip reason="the formula, not code; moved() below computes it" -->
```
moved = sqrt( sum over every weight of (after - before)^2 ) / sqrt( sum over every weight of before^2 )
```

For a LoRA model, each adapted layer counts as the one weight it
amounts to, W + (alpha / r) B A (12.02's merge). If forgetting came from
moving the weights, the model that moved further would forget more.

### The classifiers, measured as they trained

12.02's recorded run measured all of this as it went: at every
evaluation the bits on the first 2,048 tokens of Shakespeare's test text
and the distance moved, and at the end the bits on the whole test text
and on the 50 stories. So the five ways of training, three seeds each,
can be compared at the end, and also at the moment each first reached
the same accuracy on its validation questions: a method that gets
further on the task could forget more just for getting further.

### What the run does

1. The recorded run's classifiers: test accuracy, the bits on
   Shakespeare and on TinyStories after tuning, and how far the weights
   moved; Welch's t, LoRA against every weight trained.
2. Along the way: each method's bits on the 2,048 tokens when it first
   reached 0.80, 0.85 and 0.88 on validation.
3. 12.03's instruction model, here, small: 30 steps of 8 examples with
   LoRA (rank 8) and with every weight trained, 2 seeds each: exact match
   on 20 held-out instances, the bits on the first 1,024 tokens of
   Shakespeare's test text before and after, and how far the weights
   moved.

### `text_bits`

A GPT's bits per character on a text's GPT-2 tokens, read as 09.03 read
GPT-2: windows of the model's context, each token with `warm` or more
before it, made bits per character by 09.01's count of bytes.

### `weights`

The weights a GPT computes with, under the GPT's own names, each LoRA
layer counted as its frozen weight plus its change.

### `moved`

How far tuning moved a GPT's weights from where they started, as a
fraction of their length.

### `at_accuracy`

From a run's log, the bits on the untuned text when the validation
accuracy first reached a level, read on the straight line between the
two evaluations either side of it.

Parts 1 and 2 read the recorded run and print the same digits on any
machine; part 3 trains, and its last digits can differ on another.

**The head alone is GPT-2.** Its body is frozen, so it moved 0 and its
bits are GPT-2's: 1.8511 on the whole of Shakespeare's test text, 09.03's
1.851 again, and 0.8257 bits per byte on the 50 stories. Every other row
is measured against it.

**On TinyStories, LoRA forgot less.** After tuning, every LoRA rank is
0.002 to 0.007 bits per byte worse than GPT-2 on the held-out stories;
every weight trained is 0.021 worse. Welch's t, LoRA against every
weight: -2.0, -2.7 and -2.5. Every rank the same way, and each short
of the |t| of 3 that 10.05 calls beyond the noise.

**On Shakespeare, it did not.** Every LoRA rank is 0.024 to 0.033 bits
per character worse than GPT-2; every weight trained ends 0.006 better on
average, with a wide spread: its seeds end at 1.8825, 1.7833 and 1.8690,
one 0.07 better than GPT-2 and one 0.03 worse. t = +0.9 to +1.2: inside
the noise, and the other way.

**LoRA moved the weights further.** 0.0134 of their length at rank 1,
0.0080 at rank 4, 0.0066 at rank 8, against 0.0049 for every weight
trained. All of LoRA's change is in 24 matrices, W_q and W_v; rank 1's
moved most, its change counted 8 times over (alpha / r = 8, 12.02). Yet
every weight trained, which moved least, forgot most on TinyStories. The
distance moved does not order the forgetting. A move of about a percent
of the weights' length changes the untuned bits by a few hundredths:
none of these fine-tunes is close to forgetting how to write.

**Instruction tuning made Shakespeare more likely.** Thirty steps of 8
examples, both ways at the same exact match, 0.4. Every weight trained
moved the weights 0.0025 of their length and took the first 1,024 tokens
of Shakespeare's test text from GPT-2's 1.8072 bits per character to
1.708, 0.10 better; LoRA moved them 0.0061 and reached 1.792, 0.015
better; t = +3.8. Why is not measured here. A guess, and only that: the
template's short turns after a speaker's marker on a line of its own
look like a play's short speeches after a name on a line of its own.
This is a small run, 2 seeds and 1,024 tokens; and the classifier's
whole fine-tune moved the bits on the whole of the same test text by
-0.07 to +0.03 depending on its seed. A short fine-tune moves the untuned bits by a few
hundredths either way, and the direction is not a property of the
method alone.

What held: on one of two texts LoRA forgot less, at every rank, though
not beyond the noise. What did not: on the other, it forgot more, at the end and
at every level of accuracy on the way. The distance the weights moved,
the obvious measure of how much a fine-tune changed a model, does not
predict either. Not run: their benchmarks, their 7-billion-weight model,
LoRA on every layer, and training long enough to forget much.

## How it works

### One number for a whole model

```
    return (change / sum(float((w ** 2).sum()) for w in start.values())) ** 0.5
```

`change` is the sum of the squared differences of every weight, over
every tensor; the denominator the same for the weights before tuning.
The square root of their ratio is the length of the change of all 124
million numbers, laid end to end in one vector, over the length of the
starting vector. It is one number and it hides where the change is: a
change of 0.01 spread over every weight and one packed into 24 matrices
come out the same.

### The weight a LoRA layer amounts to

```
                out[name + ".weight"] = layer.linear.weight + layer.delta()
```

A LoRA layer's frozen weight never changes, so a measure that read only
the model's stored weights would say LoRA moved nothing. `weights()`
names each LoRA layer's weight as merge would make it, under the GPT's
own name, so a LoRA model and a fully tuned one are measured in the same
terms, and the comparison with the weights before tuning, which have
those names, lines up tensor for tensor.

### Between two evaluations

```
            return a["untuned_bits"] + f * (b["untuned_bits"] - a["untuned_bits"])
```

The recorded run evaluated every 150 steps, and no run is exactly at
0.85 at an evaluation. `at_accuracy()` finds the first pair of
evaluations either side of the level and reads the bits on the straight
line between them, at the fraction `f` of the way that the accuracy is.
It is an estimate, and with evaluations 150 steps apart a rough one; it
is the same rough estimate for every method.

## Decide the boundary

The measures here are bits on two texts that GPT-2 was not tuned on and
that the fine-tunes did not see: a cheap, exact measure, and one that
disagreed with itself between the two texts. A benchmark of questions,
as Biderman et al. used, measures abilities instead of likelihood, at
the price of a test set and a scorer for each. Forgetting a few
hundredths of a bit on Shakespeare costs nothing a bank's classifier
will notice; forgetting how to write a sentence would. Before calling a
fine-tune safe, which texts or tasks would you measure it on, and how
large a change would you decide in advance counts?

the measure looks in the wrong place, at the frozen weights, which never
move. Parts 1 and 2 are unchanged because the recorded run measured with
the right code when it was made. Put `+ layer.delta()` back.
