# Module 10 - Capstone: git

This module builds the core of git, in git's own formats, so that the real git reads, logs and checks the repositories this one makes, and this one reads what the real git writes. It is where the structures of the earlier modules work together. An object is named by the SHA-1 of its bytes and stored once under that name, compressed with module 09's deflate inside the zlib format; there is no slower way to set beside it, since naming by hash is the idea itself. A directory becomes a tree, an object listing its entries by name, so one change renames every tree above it and nothing else; add sorts the paths it finds with module 02's merge sort, and the index's cached trees let write-tree build only the trees that changed, 6 of 8,585 on a project of 64,000 files, though reading and writing the index keeps the time saved to about a quarter. A commit names a tree and its parents, and log walks that graph newest first with module 02's heap and module 01's hash table, where plain lists take 12 seconds on 128,000 commits against 3.4. diff walks two commits' trees side by side and passes over every subtree with the same name in both, then runs module 06's diff on each changed file: 0.005 seconds against 3.1 for reading everything, on 64,000 files. merge-base paints the history from both tips at once instead of walking one history again for each commit of the other: 3,202 commits visited against 5.1 million. Along the way the module says plainly where this git differs from the real one on purpose, to stay off repositories that matter, and what it leaves out.
