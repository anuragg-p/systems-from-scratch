# Module 03 - A text editor: edit

This module builds the track's third tool, `edit`, a text editor for the terminal, and asks one question of it: does a key cost the same in a file of ten lines as in one of ten million? The editor itself comes whole in the first lesson, the finished editor of the kilo track (derived from antirez's kilo) with its text moved behind an interface of five calls, and a replay mode that makes a script of edits with no screen, so that each structure can be timed on the same edits. The lessons are the structure behind that interface. It starts the obvious way, every byte in one array, where a key moves every byte after it: fine for typing in files of a few hundred megabytes, too slow for a frame at a gigabyte. A gap buffer keeps the free room at the cursor, so typing in one place moves nothing, and edits that jump about move a third of the file each. Undo and redo come next, as two stacks of edits on the growable array of module 01, working through the interface on any structure. A piece table never moves the text: the file is mapped, not read, what is typed goes on the end of a second buffer, and the text is a list of pieces of the two, which opens a file of any size at once but walks a longer list after every correction. The last lesson keeps the pieces in a balanced tree, an AVL tree in which each node knows the length of the text under it, so that 16000 words typed at random places in 25 MB take 16 milliseconds instead of seconds. It stands on module 00's counters and growth harness and module 01's growable array. After it, the editor opens a file of any size without copying it, and makes an edit anywhere in it in a few dozen steps.
