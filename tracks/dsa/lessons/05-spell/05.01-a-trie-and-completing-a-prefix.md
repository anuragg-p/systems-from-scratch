# 05.01 A trie, and completing a prefix

spell prints the words of a text that are not in its dictionary, and
lists the dictionary's words that start with a prefix. This lesson
builds both on a trie: a tree that keeps the words a letter at a time, so
that words which start the same share the same path down.

## Where this fits

![Where 05.01 fits](figures/05.01-map.svg)

This lesson opens module 05's column: the tool is spell, and the trie is
the first of the three pieces in its strip. Above the trie is spell, which
loads the dictionary into it, checks a text against it and asks it for the
words under a prefix. Below it is the library of modules 01 and 02: the
growable array holds the trie's nodes, the hash table is another way to
hold the dictionary, and merge sort orders the output. After this lesson
spell checks a text and completes a prefix; the Bloom filter and the edit
distance, still dashed, make it smaller and let it suggest.

## The idea

<!-- verify: fact cmd="wc -l < tools/spell/words.txt | tr -d ' '" expect=60388 -->
<!-- verify: fact cmd="wc -c < tools/spell/words.txt | tr -d ' '" expect=563527 -->

spell's dictionary is `tools/spell/words.txt`: 60388 English words, one to
a line, 563527 bytes (Alan Beale's 2of4brif list, in the public domain).
spell has two jobs: print each word of a text (a run of letters,
lowercased, as freq reads them) that the dictionary lacks, and, with `-p`,
print every dictionary word that starts with a prefix, as a search box
completes what you have typed.

The obvious way is a list: the words in an array, and a lookup that
compares the word with each in turn. The first Unix spell worked that way;
Doug McIlroy wrote of it that "the program had to scan the entire
dictionary". A word that is not there costs all 60388 comparisons. On the
Sherlock Holmes book the list looks at 3.47 billion dictionary words and
takes 4.2 seconds on this machine, an Apple M4 Pro; a text ten times as
long takes ten times as long.

The hash table of module 01 fixes the check: the book takes 0.02 seconds.
But a hash says nothing about how a word starts. "quoit" and "quorum" land
in unrelated buckets, so to complete `qu` the table looks at all 60388
words and sorts the 291 that match, on every keystroke.

A **trie** keeps the words a letter at a time down a tree. The root stands
for the empty prefix; each node has a child for each letter that comes
next in some word, and a mark where a word ends. "car", "cart" and "cat"
share the nodes for "c" and "ca":

![The trie for car cart cat dog, built by spell from their trace: each word walks down from the root and makes the nodes it lacks; checking cab stops where no child b exists; -p ca walks to the node for ca and lists car, cart and cat below it](figures/05.01-trie.svg)

Looking a word up is one walk down, a node a letter: "cab" goes c, a, and
finds no child for b, after three steps however many words the trie
holds. Completing a prefix is the same walk, to the prefix's node; every
word below it starts with the prefix, and no other word does. Taking the
children from a to z brings them out in order, with no sort.

<!-- verify: fact cmd="DS_STATS=1 bin/spell /dev/null 2>&1 | sed -n 's/.*nodes \([0-9]*\),.*/\1/p'" expect=138676 -->

The price is memory. Each node has room for all 26 children, used or not,
so that a step down is one array access. The dictionary takes 138676
nodes and 28.3 MB: fifty times the word list as text, eight times the hash
table. The trie buys no speed on the check, where the table is as quick;
it buys prefixes, and in 05.03 a search that can skip whole subtrees.
05.02 wins the memory back for the check.

### `trie_add`, `descend` and `walk`

`lib/trie.c` keeps the nodes in one growable array (01.01); a child is a
node's index in it. `trie_add()` walks down from the root, making each
missing node, and marks the last as the end of a word. `descend()` is the
walk down for `trie_has()` and `trie_find()`: the node at the end of the
path, or -1 at the first letter with no child. `walk()` visits everything
below a node, children from a to z, handing each word to a function.

### `list_has`, `complete_scan`, `complete_trie` and `check`

In `tools/spell/spell.c`, `--algo=list|table|trie` says what holds the
dictionary (trie by default); the slow ways stay runnable. `list_has()` is
the list's lookup, counting each word it looks at. `complete_scan()` is
`-p` for the list and the table: every word looked at, the matches sorted
with merge sort (02.02). `complete_trie()` is `-p` for the trie.
`check()` keeps each unknown word of two letters or more; `main()` sorts
them and prints each once.

## How it works

### A child is an index, and 0 means none

A node holds `int32_t child[26]`, the index of the node for each next
letter. Not a pointer: when the growable array is full, pushing a node
moves the whole block to a bigger one (01.01), and a pointer into the old
block would point at freed memory. An index stays good, which is why
`trie_add()` takes the parent again, by index, after the push:

```
            next = (int32_t)t->nodes.len;
            memset(array_push(&t->nodes), 0, sizeof(TrieNode));  /* may move the nodes */
            node_at(t, node)->child[c] = next;
```

The root is node 0 and no one's child, so a child of 0 can mean "no
child": a new node, all zeros, has no children and is no word without a
field to say so. The **invariant**: every child that is not 0 is the index
of a node already in the array, made after its parent (the figure numbers
nodes in the order they were made).

### A prefix is not a word

The path for "ca" exists because of "car" and "cat", but "ca" is no word.
Each node has a mark, `word`, set only where an added word ends, and a
lookup must check it after the walk; `trie_has()` does:

```
    int yes = node >= 0 && node_at(t, node)->word;
```

`walk()` checks it too, and hands a word to the printer before going
deeper, so "car" comes out before "cart". A word sorts before every longer
word that starts with it, so children from a to z, each word before those
below it, is byte order: the order `look` prints from a sorted file.
`complete_scan()` has to sort.

### Where the 28 MB go

A `TrieNode` is 26 four-byte children and a one-byte mark: 105 bytes,
padded to 108 so the next node's children line up. 138676 nodes are
14977008 bytes; the array doubles as it grows, so its block holds 262144
nodes, 28311552 bytes. Of the 3605576 children in the nodes used, 138675
are not 0, one for each node but the root: 3.8%. Nearly all of the trie is
zeros. The list takes 1612103 bytes and the table 3709255.

## Decide the boundary

This trie gives every node 26 children: a step is one array access, and
the trie is fifty times the text. Another program could binary-search the
sorted word list, as `look` does in 02.06.

<!-- verify: fact cmd="DS_STATS=1 bin/look qu tools/spell/words.txt 2>&1 >/dev/null | sed -n 's/.*probes \([0-9]*\),.*/\1/p'" expect=17 -->

`bin/look qu tools/spell/words.txt` finds the first of the 291 words in 17
probes and reads on, in no more memory than the text. What a sorted list
cannot do is share work between words that start the same: 05.03 walks the
trie once for a misspelling and skips every subtree that cannot hold a word
near it. A third design keeps the tree with smaller nodes (a short list of
the children that exist, or a ternary search tree) and pays with slower
steps. Do you need prefixes as a range of a sorted list, or as a tree that
other searches can walk and cut?

## Break it

Forget that a prefix is not a word. In `build/at/dsa/05.01/lib/trie.c`, in
`trie_has()`, drop the check of the mark. First, three words as the code
stands:

<!-- verify: session -->
```
$ printf 'inspec accompli acquaint\n' | bin/spell
accompli
inspec
```

Then change `int yes = node >= 0 && node_at(t, node)->word;` to
`int yes = node >= 0;`, build, and run the same three words and the book:

<!-- verify: patch file=lib/trie.c old="int yes = node >= 0 && node_at(t, node)->word;" new="int yes = node >= 0;" -->

<!-- verify: session
line 4 ~ \s*552
-->
```
$ make -s
$ printf 'inspec accompli acquaint\n' | bin/spell
$ bin/spell data/book.txt | wc -l
     552
```

Every walk that does not fall off the trie now counts as a word, and the
start of any word is such a walk: "inspec" and "accompli" begin "inspect"
and "accomplish". On the book 63 of the 615 unknown words go quiet (ado,
blanche, bohemia, carlo, de, dr, etc, th, ...), each the start of a longer
word. The trie is unchanged; only the question asked of it is wrong. Put
the line back before going on.
