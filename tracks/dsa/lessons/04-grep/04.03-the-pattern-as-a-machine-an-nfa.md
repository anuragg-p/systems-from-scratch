# 04.03 The pattern as a machine: an NFA

The backtracking matcher of 04.02 can take longer than anyone will wait on
one ordinary line of the book, with a pattern someone would really write.
This lesson turns the pattern's tree into a machine of states, as Ken
Thompson did in 1968, and runs it in every state it could be in at once, so
that each byte of the line is read once, and the work for it is never more
than the machine has states.

## Where this fits

![Where 04.03 fits](figures/04.03-map.svg)

The NFA is the third box of module 04's strip. It is built from the tree
the parser of 04.02 makes, and from this lesson grep runs it instead of the
backtracker unless asked (the backtracker stays, for comparison). It needs
nothing from the library: an array of states and two lists of state
numbers. After this lesson no pattern can make grep take more than the
bytes of a line times the states of the machine, and the next lesson makes
each byte cheaper still.

## The idea

![The machine for a?a?a?aaa reading aabaaa, one byte a frame: the machine drawn once, and the states it is in after each byte filled in.](figures/04.03-nfa.svg)

Lines made only of words and spaces: `^([A-Za-z]+ ?)*$`. The backtracker
prints the ones among the book's first 40 lines in half a second, and then
nothing more. Line 41 takes it 3.3 seconds, and line 43, by the count
below, about eight hours.

Look at what it tries. The loop goes round once for each piece of a line,
and a piece is letters and then a space or no space. So a word of k letters
can be read as one piece, or cut into two pieces anywhere between its
letters, or three, or k: there are 2^(k-1) ways to cut it, and the ways for
each word multiply. A line that ends in a full stop fails only at the `$`,
after every way has been tried. Line 41, "throw a doubt upon all his mental
results.", has 34 letters in 8 words before its full stop: 2^26 ways, 951
million steps, about 14 steps a way at about 300 million steps a second.
Line 43 has 2^39 ways, and line 58 2^48, which at that rate is about five
months.

Every one of those ways is wasted work after the first. Having read
"throw", the match is at the same place in the pattern, inside the loop
just after a letter, however the word was cut, and what happens next
depends only on that place and the rest of the line. So keep the places,
not the ways: after each byte, the set of places in the pattern the match
could have reached. The set never holds a place twice, so it is never
larger than the pattern.

The places are the states of a machine. **Thompson's construction** turns
the tree into one: a **state** for each byte the pattern reads, which reads
that byte and goes on to the next state; a **split** for each choice, which
goes on to two states at once and reads nothing; and a **match** state at
the end. A machine that can be in several states at once is a
**nondeterministic finite automaton**, an **NFA**. To run it, keep the list
of its **live** states. For each byte of the line, each live state that
reads that byte moves on, and the states it moves to, with every split
after them followed, are the next list. A match may begin at any byte, so
the start state is added again after each one.

The figure runs the machine for `a?a?a?aaa` on aabaaa. After two a's it is
in 6 states; the b kills every partial match at once, and the start, added
again, brings back the first four. Nothing is tried twice, nothing is
undone, and the match is found at the last byte.

### `build`

Thompson's construction, written backwards: it is given the state a node
leads to and returns the state to start the node in. A sequence builds its
right side first, so the left side knows where it leads. A `|` is a split
to both sides; `?` a split to the part and past it; `*` the same, with the
part leading back to the split; `+` the part first, then a split back to it
or on. `size()` counts each part's states before it is built, so the
states are numbered in the order the pattern is written.

### `nfa_compile`

The machine for a whole pattern: room for its states, a match state last,
and `build()` for the tree.

### `nfa_add`

Puts a state on a list, and follows every arrow out of it that reads
nothing: both ways of a split, a `^` only at the start of the line, a `$`
only at its end; a `$` before the end stays on the list, waiting. Each
state has a mark, so it goes on a list at most once.

### `nfa_match`

Runs the machine on a line with two lists, the states live now and those
live after the next byte, swapping them after each byte. It stops at a
match, or when no state is live. In `grep.c`, `use_regex()` builds the
machine for every engine but the backtracker, and `--algo=nfa` is the
default.

## How it works

### Why the set never needs to go back

The **invariant**: the list after byte i holds every state the machine
can be in after reading the line up to i, from a start at any byte so far.
The loop of `nfa_match()` keeps it, making the next list from this one and
the byte alone. The backtracker went back to undo one way and try another;
the list follows all of them at once, and two ways that reach the same
state at the same byte are one entry, since from there on they do exactly
the same. So no byte is ever needed again. The work is at most the line's
length times the machine's states, and the machine has at most one state
for each byte of the pattern, and the match state: a byte, a bracket
expression or an anchor is one state, a `|`, `*`, `+` or `?` one split, a
parenthesis none. The pattern's length, not its shape, bounds the time.

### A state goes on a list once

```
    if (m->mark[id] == m->gen)
        return;
    m->mark[id] = m->gen;
```

`nfa_add()` marks each state with the number of the list being built, and
`nfa_clear()` starts a new number for each list, so emptying a list costs
nothing. The mark does two jobs: a state reached two ways is kept once,
which is what keeps the list no longer than the machine, and a loop of
splits that read nothing, such as `(a*)*` makes, ends the second time
round instead of going for ever. That is the guard the backtracker needed
a special case for.

### What "regular" means

The machine has a fixed number of states, and its list of live states is
all it remembers of the line so far. What a machine like this can match
are the **regular** languages, which gave regular expressions their name.
Back references (`\1`: the text group 1 matched, again), which many
backtracking engines have and this dialect leaves out, need the text itself
remembered, and are not regular: Russ Cox's article says no one knows how
to match them efficiently.

## Decide the boundary

The backtracker is short and stretches to back references, and it takes
time that can double with every byte of a line. The NFA cannot do back references, and its time
is never more than the line's bytes times the pattern's states. Perl,
Python and Ruby backtrack; awk, GNU grep and RE2 build machines. Do the
patterns your program runs come from you, or from people you do not know?

Only matches that start at a line's first byte are found now: 42 lines
begin with "Holmes". The live states that read a move on and nothing comes
in behind them, so the list shrinks, and at the b it is empty and the line
is given up, although aaa follows. The anchored words pattern still finds
its 3200 lines, since its matches start at the line's start anyway. Put
the two lines back.
