# 01.01 Three loops and a reference

Matrix multiply is written here twice, as `add` was in module 00: a
reference that keeps every sum in a double, and three plain loops in
floats, the first rung of the ladder this module climbs. The lesson also
settles how close a float answer must come to the reference, and why that
close and no closer.

## Where this fits

![Where 01.01 fits](figures/01.01-map.svg)

Module 01 is the left column of the map: one operation, matrix multiply,
made faster on the CPU in five steps, each checked by the workbench before
it is timed. This lesson is the bottom rung: the plain loops, and the
reference every rung above is held to. The next four change the order
memory is read in, the floats one instruction works on, how much of the
matrices is in use at once, and how many cores work. After this lesson the
workbench can check and time a matrix multiply.

## The idea

![One element of c: a row of a times a column of b](figures/01.01-row-times-column.svg)

A matrix multiply takes a, m rows by k columns, and b, k rows by n columns,
and gives c, m rows by n columns. Each element of c is one row of a times
one column of b: c[i][j] is the sum over p of a[i][p] x b[p][j].

Take a with rows (1, 2, 3) and (4, 5, 6), 2 x 3, and b with rows (7, 8),
(9, 10) and (11, 12), 3 x 2. c is 2 x 2. Its element c[1][0] takes row 1 of
a, (4, 5, 6), and column 0 of b, (7, 9, 11): 4 x 7 + 5 x 9 + 6 x 11 = 28 +
45 + 66 = 139. Every element of c is a sum of k products like that one.

In memory a matrix is one array of floats, stored **row by row**: row 0,
then row 1, and so on. Element a[i][p] is `a[i * k + p]`: skip i whole rows
of k floats, then go p along. The example's a is the six floats 1 2 3 4 5 6,
and a[1][0] is at 1 x 3 + 0 = 3, the 4. Likewise b[p][j] is `b[p * n + j]`.

### `matmul_ref`

The reference is the definition written as three loops, with each sum kept
in a **double**, which carries 29 more bits than a float. The comment above
it gives the reason: its rounding errors are hundreds of millions of times
smaller, so next to a float sum it is the exact answer, rounded once at the
end. It is never timed.

### `matmul_ijk`

The same loops with the sum in a float, in the order the formula reads: i,
then j, then p, hence the name. Every table in this module says how many
times faster than it the others run. Its inner loop walks down a column of
b, n floats a step; lesson 01.02 is about what that costs.

### mm check

`mm` is the program this module grows, as `wb` was module 00's. `mm check`
runs each variant on eight shapes and holds every element to the
reference's with `check_close`. It prints one line a variant: the first
shape it fails on, or the largest when it passes them all.

### one call of a variant, as bench calls it

`bench` calls a function with one pointer. `struct mm_args` holds the
variant and its matrices, and `run_variant` calls it on them.

### mm time

`mm time` fills two n x n matrices from seeds 1 and 2, with n = 1000 unless
`-n` says otherwise, times each variant with `bench`, and prints its fastest
run, its speed, and how many times faster than ijk it ran.

## How it works

### Room between rounding and a mistake

Every check in this module uses one tolerance:

```
#define RTOL 1e-4
#define ATOL 1e-3
```

An element is good when it is within 0.001 + 0.0001 x |want| of the
reference's. The size comes from two numbers. A float sum of k products of
numbers in [-1, 1) rounds after every add, and drifts from the exact sum by
some square root of k rounding errors of its running total, about 1e-4 at k
= 2048 (the comment above the two lines). Measured while this track was
built, at n = 2000, ijk's largest error over all of c was 1.79e-04, and its
element closest to the limit used 0.065 of its allowance. A real mistake, a
term left out or a wrong index, moves an element by a whole product or
more. Break it below measures one.

### c starts as NaN

```
            for (int i = 0; i < m * n; i++)
                got[i] = NAN;
```

Before every call c is filled with NaN, which is never close to anything.
A variant must set every element of c, not add to what is there, and an
element it forgets keeps its NaN and fails, instead of holding whatever
that memory held, which could be right by luck.

### Shapes that are not square

```
static const int shapes[][3] = {
    {1, 1, 1}, {3, 5, 7}, {8, 8, 8}, {33, 31, 65}, {64, 64, 64}, {100, 200, 50}, {129, 65, 63}, {256, 256, 256},
};
```

Four of the eight are not square: 3 x 5 x 7, 33 x 31 x 65, 100 x 200 x 50
and 129 x 65 x 63. In them m, k and n all differ, so an index that uses k
where n belongs points somewhere else; on a square shape the mistake cannot
show. Three have no side that is a multiple of 4 (3 x 5 x 7, 33 x 31 x 65,
129 x 65 x 63): later lessons' loops go several columns a step and finish
with the columns left over, and these sizes always leave some.

## Decide the boundary

This reference is slower and more exact than any variant: the same sums,
in a double. The other kind is the same arithmetic done plainly, as
`add_ref` is: the same float operations in the simplest order. With the
first, every variant has one truth to be near. The cost is that even the plain float loop
does not match it exactly, so every check needs a tolerance, and a reason
for its size. With the second, a variant that does the same operations in
the same order can be held to `==`, as `add` was; but the faster variants
in this module do not all round as the plain loop does, and would differ
from it anyway.
Is your reference the right answer, or the plainest way of getting one?

## Break it

Leave one term out of every sum: in `build/at/gpu/01.01/matmul.c`, in
`matmul_ijk`, change the inner loop's test so that the line reads
`for (int p = 0; p < k - 1; p++)`. Build and check:

<!-- verify: patch file=matmul.c
             float sum = 0;
-            for (int p = 0; p < k; p++)
+            for (int p = 0; p < k - 1; p++)
-->
<!-- verify: session -->
```
$ make -s
$ ./mm check; echo $?
ijk     1x1x1: FAIL, 1 of 1 wrong; worst at [0]: got 0, want -0.0540636703 (error 0.0541, allowed 0.00101)
1
```

It fails on the first shape, 1 x 1 x 1, where the one term left out is the
whole sum: want is a[0] x b[0], -0.438330 x 0.123340, the first values of a
and b that `wb show` printed in lesson 00.01, and got is 0. The error is
about 54 times the allowance. The right ijk's worst, in Run it, used less than a
hundredth of its allowance. Between what rounding does and what one missing
product does there is room, and the tolerance sits in it. Put the line
back.
